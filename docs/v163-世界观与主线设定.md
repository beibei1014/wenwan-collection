## 1. 【命名方案】

> **v163-b 修订**：初稿主推的「灵犀」已被用户否决（原话：「不能叫灵犀！！！！！换个名字！！！！！」），**彻底出局，不再讨论**。本节为按主理人裁决重写的定稿，统称改为 **沁灵**。

### 1.1 结论

> ## 统称：**沁灵**
> 量词：**一尊**（正式/图鉴/统计）· **一只**（日常/对话）
> 昵称：**沁儿** · 老辈：**老沁**（仅群像对话偶用）
> 诞生：**开沁**（术语）/ **醒**（口语）
> 进阶：**深沁**（原「突破」）

### 1.2 为什么是「沁灵」

判据仍是**通名三连测**：「一只\_\_」/「这些\_\_」/「我的\_\_们」都要通顺。

| 候选 | 通名三连测 | 判定 |
|------|-----------|------|
| **沁灵** | 一只沁灵 ✓ / 这些沁灵 ✓ / 我的沁灵们 ✓ | ✅ **定案** |
| ~~灵犀~~ | ✓ | ❌ **用户否决**。且它天生是抽象名词——现代汉语里"灵犀"首先是"心意相通"**那件事**，不是一只东西。沁灵正好反过来：**先是一件被沁过的器物，然后才是那段关系** |
| 物华 | ✗ | ❌ 集合名词（"物华天宝"），无法个体化 |
| 琳琅 | ✗ | ❌ "琳琅满目"天然复数、不可数 |
| 岁华 | ✗ | ❌ 抽象名词（光阴） |
| 掌珍 | △ | ⚠️ 语法勉强，但"掌上珍"自带商品名气味 |
| 尘灵 | ✓ | ⚠️ "尘"字对文玩是**忌讳**（盘玩最怕落灰），且中式出处为零 |

**沁灵胜出的三条理由：**

1. **它是唯一一个"行话级"的词——而且这个词已经在 APP 里了。**
   「沁色 / 沁入 / 沁进去」是文玩圈术语：外来物质沿裂隙渗入玉体形成的颜色变化。**`js/tips.js` 里就有**：`:370`「沁入油脂后再上手」、`:373`「沁进去」、`:307`「沁出后越来越润」。
   **它不是我发明的文绉绉新词，是玩家自己每天在用的那个词。** 沁灵 = **沁进去的灵**。而整个盘玩行为，本质上就是"沁"：汗、油、体温、时间，一层层沁进一件死物里。世界观那句核心「人心久注，器物生灵」，翻译过来**就是"沁"这一个字**。

2. **它天生是动作，不是状态。**
   灵犀 / 琳琅 / 岁华全是静态名词，沁灵自带"正在渗入"的进行时——跟"养"这件事严丝合缝。
   更重要的是：它给了整套术语一条共用的根——
   **沁 → 开沁 → 深沁 → 沁透 → 沁过头 = 石心**
   **全书最大的那个反转（石心），就长在这个字上。** 这是灵犀给不了的结构性收益。

3. **三连测全过，气质对。**
   一只沁灵 / 这些沁灵 / 我的沁灵们，全通顺。两字、常用字（沁人心脾）、无多音字、输入法零门槛。冷、雅、有匠气，不甜不黏不网文，彻底避开情诗那条路。

定义句（印在图鉴首页 / 新手引导第一屏 / 终章回扣）：

> **沁者，渗入也。人心久注，气自指尖渗入，日久生灵，聚而成形者，谓之沁灵。**

### 1.3 配套词表（四项全答）

#### ① 量词与称呼

| 场合 | 用法 | 示例 |
|------|------|------|
| 正式 / 图鉴 / 统计 | **一尊** | "共 12 尊"·"这一尊是去年开沁的"·"沁灵总数 12 尊" |
| 日常 / 剧情 / 对话 | **一只** | "有一只不肯化形"·"这三只住一间" |
| 亲昵 | **沁儿** | "沁儿，过来" |
| 老辈（`bornAt` 最早的） | **老沁** | "老沁说了才算"（仅群像对话偶用，低频） |
| 复数 | **沁灵们** | "我的沁灵们" |

> 为什么正式量词选"尊"而不是"位"：**"位"把它当人，"只"把它当物，"尊"把它当"有灵的器物"**——正好是这个世界观的位置。这是全套命名里我最想保住的一个字。

#### ② 「成精 / 化形」这个动作 → **开沁**

> ## **开沁**

**为什么是"开"**：文玩行话里"开"就是起始动词——开光、开脸、开片。「开沁」既有行业感，又有"**开始沁入**"的字面义，一件事的起点。

**被否掉的两个**：
- **「沁灵」** ✗ —— 和统称同名，"它沁灵了"读起来是"它变成了一只沁灵"，术语和名词打架。
- **「沁醒」/「醒沁」** ✗ —— 语序别扭，且"沁醒"得加"被"才通顺（"被沁醒"），做不了主动式动词。

**造句全验证**：

| 场合 | 文案 | ✅ |
|------|------|---|
| 动词 | "它开沁了"·"第 37 天，它开沁" | ✓ |
| 事件名 | **开沁之日** | ✓ |
| 未状态 | "还没开沁的珠子" | ✓ |
| 排序 | "按开沁早晚排序" | ✓ |
| 卡司 | "开沁最早的三**尊**" | ✓ |
| UI 按钮 | ✨ 开沁 | ✓ |
| 代码字段 | `rec.bornAt` **保留不动**，注释改为「开沁时刻」——改文案不改字段，零迁移成本 | ✓ |

**口语说「醒」，而且现有剧本已经在用了**——`CHAP_SCRIPTS` 第一章「就是那一下，我醒了。」、`GREET.born`「刚醒过来，手心还是热的。」**这两处一字不用改**，术语（开沁）与口语（醒）分工，正好。

⚠️ **一处必须用"醒"避开叠字**：空状态文案不能写"还没有沁灵开沁"（沁沁重复）。正确写法是 **「还没有沁灵醒过来」**。

> 附带：行文里要表达"正在沁"的过程义时，用 **起沁**（玉石行话的构词法——起胶 / 起荧光 / 起刚）。"它身上起沁了。" 这是过程，开沁是那个瞬间。

#### ③ 进阶动作 → **深沁**（原「突破」，原拟「蜕形」已废）

⚠️ **冲突已解决**：初稿把进阶动作定为「蜕形」，但它同时是**第 3 阶的阶位名**，一个词两个意思，会混淆。按主理人裁决——**4 形态名（凝形/开窍/蜕形/化形）保留不动**，所以改的是动作。

> ## **深沁** = 沁得更深一层。每一次突破，就是沁得更深一层。

**造句验证**：它深沁了 ✓ · 第三次深沁 ✓ · "攒够了，可以深沁了" ✓（正好对应现有 `GREET.break_able` 的"攒够了。什么时候都行，我听你的。"）· "深沁之后会长高一截" ✓

**结构性收益（这是换词最大的收获）**：它把进阶动作**直接接到了终极威胁上**——

> **沁 → 深沁 → 沁透 → 沁过头 = 石心**

玩家每点一次「✨ 深沁」，都是在把石心往前推一步。**全书最大的反转，现在长在 UI 按钮上。**

**代码替换点**：`app.js:3011`「✨ 可突破」→「✨ 可深沁」· `app.js:3497`「突破中…」→「深沁中…」· `app.js:3559`「突破失败：」→「深沁失败：」

## 2. 【世界观】

### 2.1 一句话概括

> **人心久注，器物生灵。** 文玩是被"养"的——人把体温、时间、注意力一层层"沁"进一件死物里，沁够了，它就醒了；醒了之后它才发现，养它的那个人，才是它会消失的原因。

### 2.2 为什么偏偏是「文玩」

这是整套设定的地基，必须答得死。

世上的东西都有人用，但**只有文玩是被人"养"的**。碗是拿来盛饭的，车是拿来开的——人用的是它们的**用处**。唯独文玩，人摩挲它**没有任何用处**：不能吃、不能穿、不产生任何效率。人日复一日地盘一串珠子，手上没有任何产出，唯一被改变的是**那串珠子本身**。

这就是关键：**盘玩是人类唯一一种"以改变一个物件本身为目的"的长期行为。**
在设定里，这叫做——

> **「养灵」**：凡被人长年以手温养、无所求而摩挲者，人气自指尖沁入，日久则生灵。

所以不是"老物件会成精"（那是《聊斋》的旧套路，而且解释不了为什么碗和桌子不成精）。是**"被养的"才成精**。碗和桌子被用，不被养；珠子被养，所以珠子醒。

而"养"的具体动作，就是文玩行话里那个字——**沁**。油脂、皮脂、体温、空气，一层一层沁进去。

### 2.3 力量体系：包浆就是修为

这是我认为最值钱的一条设计——**它把用户已经玩腻的"盘亮/包浆"，从日常话题升格成了修行体系**。以后我们不再写"今天盘亮了"这种日常流水账（用户明确嫌弃），而是把包浆当成**境界的刻度**，只在关键节点提它：

| 文玩术语 | 现实含义 | 设定中的修行阶段 | 对应阶位 |
|---------|---------|----------------|---------|
| **挂瓷** | 表面泛起玻璃光泽 | 灵气初聚，勉强凝形 | 凝形 |
| **上色 / 沁色** | 颜色由浅入深 | 灵气入体，开了窍 | 开窍 |
| **包浆** | 温润的琥珀色宝光层 | 修为小成——**包浆的厚度 = 修为的年头** | 蜕形 |
| **玉化** | 通透如玉 | 化形；但也是一条不归路 | 化形 |
| **石心** ⚠️ | （现实现象：过度盘玩失去光泽、发死） | **修行的终点，也是终点**——见 2.5 | — |

配一句可以进图鉴的话：
> **"包浆不是脏，是它活过的年头。"**

### 2.4 规则与代价

六条规则，每条都**能挂到一个现有字段上**——这是它们能被写进程序的前提。

| # | 规则 | 内容 | 挂靠字段 |
|---|------|------|---------|
| 一 | **养则长，弃则退** | 人气是它唯一的食粮。你盘它，它就长；你冷落它，它就**退形**——不是死，是**往回缩**：话说得慢了、记不清事了、形体变淡。退到底，就散回一串普通珠子，并且**忘光一切** | `ctx.idleDays` / `ctx.plays` |
| 二 | **望之即忘** | 它不是隐形。别人看得见，但**十秒内就会当成看错了忘掉**。只有养它的人看得住它。被不相干的人长久注视，人气会被**分薄** | —（供剧情用） |
| 三 | **名即契** | 无名之灵是浮的，容易散。主人给它起了名字，就等于**结契**——契一成，名字**不能再改**。这也是为什么 APP 里"每只只能改一次" | `rec.persona.name` + 改名只能一次的现有限制 |
| 四 | **沁线** | 主人和它之间有一道看不见的线，线的粗细 = **亲密度**。线细则它只能说些安全的话；线粗到「同心」，它能**在你进门的那一刻看出你今天怎么样** | `rec.bond` / `bondLv` |
| 五 | **过气** | 沁灵之间可以互相过人气。同屋的串会彼此滋养——所以群居比独居长得快，也所以**一只串可以把自己暗下去，把光让给另一只** | `Rooms` 的 `ww_bonds.affinity` |
| 六 | **日落归体** | **它的本体永远是那串珠子。** 化形只是"显形"，不是变成人。它睡觉要回珠子里去；化形之后能出门走一天，**但天黑之前必须回来**。回不去，就散 | —（供剧情用，卷四第 10 章的核心冲突） |

再补一条**时间感**的差异，它解释了产品里最戳人的那个设定：
> 人睡着的时候，它醒着。人不在的三个月，在它那里是整整一年。
> ——所以你三天没来，它像是等了很久。**这不是修辞，是设定。**

### 2.5 三层威胁（撑长线的骨架）

不是单一大魔王，是**三层由近及远的恐惧**，玩家可以一层层撞上去：

| 层 | 名称 | 是什么 | 恐怖感来源 | 出场位置 |
|----|------|--------|-----------|---------|
| **近** | **退形** | 你忘了它，它就变淡、变笨、忘记你 | 愧疚。而且是你造成的 | 卷三第 6 章 |
| **中** | **扫尘人** | 一脉相传的收旧物者。他们真心相信"物老成精，久则为祟"，见到养出灵性的旧物就收走、封进**衬红布的铅盒**、贴朱砂封条，让它灵气散尽。**他们不认为自己在作恶，他们认为自己在打扫** | 他们有**正当性**。而且他们看得出来——他们管这叫"这件养过头了" | 卷二第 5 章（传闻）→ 卷三第 7 章（上门） |
| **远** | **石心** | 玉化的尽头。盘得越多它越通透，通透到某个临界，它会**彻底玉化——变成一块永远不会说话的死物**。它还保持着最后那个表情，还是笑着的，但它不再回答你 | **玩家一直在做的那件事，就是杀死它的那件事** | 卷四第 11 章（发现）→ 卷五（抉择） |

**石心这条是全书最重要的反转**，请务必保住：玩家全部的游戏行为（盘、养、突破、追求化形）都是通往失去它的路。终章要玩家**主动停止玩这个游戏的核心动作**，才能留住它。

> **石心的判词**（这句会同时出现在 CG-07 相册题词和终章）：
> **"它成了。成了，就不说话了。"**

### 2.6 隐藏的秩序与中立者

- **扫尘人**：散在古董商、废品回收、搬家清货的人里。识别方式是看包浆——"太亮了"。他们的工具：铅盒、红布、朱砂封条、一句"这件养过头了"。压在盒里的沁灵**不会死，只是永远睡着**。
- **老陈（中立 NPC，可选）**：巷口旧货铺的老板。一个**看得见但从不说破**的凡人。他是全书唯一的信息源和道具源（朱砂、旧盒、一块能"压住"玉化的石头）。
  > 设计意图：**他不需要立绘、不需要出图、不占卡司位**，只在对白里出现。低成本，高功能。

### 2.7 胎性 —— 100 只串复用同一套剧本的根基

用户有 100+ 只串，**绝不能为每只单独写剧情**。解法是给每一只打一个**胎性**标签，剧本里用 **`{tixing}`** 变量注入，一套剧本读出一千种味道。
> ⚠️ 占位符**一律用 ASCII key**（`{tixing}` 而非 `{胎性}`）：主线走 `fmt`（硬编码 replace 链）、夜话走 `thText`（正则 `/\{(\w+)\}/g`，`\w` 不匹配中文）。ASCII key 让两条路径同时安全。详见 `v163-主线剧本-沁灵纪.md` §7。

胎性**由 `item.species` 直接推导**（纯函数，无需新数据）：

| 胎性 | 覆盖品种 | 性格倾向（对应 `PERSONAS_PICK`） | 剧作功能 |
|------|---------|--------------------------|---------|
| **木胎** | 菩提根、金刚、凤眼、千眼、库克、椰壳、核桃、橄榄核、象牙果、紫金鼠 | calm / mystery | 慢、记性好、老成。适合"守""记""忍" |
| **石胎** | 和田玉、翡翠、南红、绿松、玛瑙、岫玉、青金、黑曜石、各类水晶 | cool / gentle | 冷、通透、**能照见人心**。也脆。适合"看穿""沉默""碎" |
| **脂胎** | 蜜蜡、琥珀 | lively / cheeky | 软、暖、黏人、**怕热**。适合"撒娇""依赖""融化" |
| **金胎** | 金银配饰、铜件、金属类 | cool / lively | 烈、响、护主，但招灰。适合"冲""挡""锈" |
| **杂胎** ⚠️ | 拼图、盲盒、手办、周边（`category` 为拼图/动漫周边/盲盒） | 任意 | 见下 |

> **杂胎的设定补丁（必须写，否则世界观破洞）**：本 APP 的 `categories.js` 里还有拼图 / 动漫周边 / 盲盒三类非文玩。补丁是——
> **"养"不只靠手，也靠眼睛。** 一片片拼起来的时间，是养；一个摆件被长久地注视，也是养。只是**慢得多**。
> 一句话收编全部品类，世界观自洽。

**胎性对文案的价值**：同一章剧本，木胎说"我记得"，石胎说"我看见了"，脂胎说"我怕"。**一稿三写，只靠变量。**

> **正文落点（v163-c 补）**：`{tixing}` 已写进剧本正文两处——第 5 章它自陈「我是{tixing}的。他那种人，一眼就能看出谁是养过的。」（把第 11 章石心的引信提前）；第 12 章它自陈「我是{tixing}的。我本来能一直长下去，长成你要的那种东西。现在长不成了。」
> 初稿只把它写在变量表里、正文一次没用——**等于白设计**。已修。

### 3.2b 门槛修订说明（v163-c · 与互动设计师游心流联合修订）

初稿门槛**有节奏事故**，已按游心流的时间账重算。依据是代码里现成的公式：`settleBond`（:1913，首启 `bond=min(40,days)`，之后 `dAdd=min(90,Δdays)*2`、`pAdd=min(20,Δplays)`）、`growthOf`（:440，`plays*3+days`）、`STAGES` need 0/30/90/180。

**四种原则：**

1. **`days` 退出硬门槛，改当余味修饰。** 它是玩家唯一无法主动加速的量；当门槛 = 把叙事节奏外包给日历。仅第 1–2 章的 `days≥1/≥7` 保留（足够短），第 5 章起只作**并列兜底**或**台词注入**（"陪你的第 {days} 天"）。
2. **主轴换 `bond`。** 日增速 A3 / B5 / C2.33，玩家差异仅 2 倍，且多盘多开都涨——推得动也不失控。（对比：`plays` 差异 3 倍，`days` 差异 0 倍）
3. **`plays` 只留石心线（第 10/11/12 章），且必须配 `days` 兜底。**
4. **相邻章间隔 ≤ 21 天。**

**修订效果**：全书 A 型 80 天 / B 型 48 天 / C 型 103 天，最大间隔 20 天。（初稿：前 9 章挤在 23 天内放完，然后空窗 135 天，第 12 章卡在第 365 天。）

**三处结构补丁（不只是"改数字"）：**

| # | 问题 | 补丁 |
|---|------|------|
| **D1** | 第 6 章 `idle≥7` **死锁**——日活玩家恰恰最不可能冷落 7 天 → 第 6 章永不解锁 → 因 `chapterState` 的 `prevRead` 串行锁，第 7–12 章**全部锁死** | 加 `days≥40` 兜底（`anyOf`）；并**补写一版分支**：不是"你冷落了它"，而是"它自己开始淡了"——没人做错任何事，这版更虐 |

### 4.3 ⚠️ 给架构师的关键提案：「无因池」

上表里有几条（T01 家里来人、T12 你今天没说话、T13 搜索记录）**无法从任何数据字段推导**——程序不知道你今天有没有客人。但恰恰是这几条最有人味。

我的提案：新增一种事件触发源——

```js
when: { always: true, cool: 14 }   // 不依赖任何数据；每 14 天最多触发一次
```

配套规则：
- 无因事件**单独一个池**，与"有因事件"（生日/节令/亲密度）互不挤占。
- 冷却天数写死在事件上，事件之间错开（14/21/30 天）。
- 文案上**不写死"今天"**，写"那天/有一回"——这样即便玩家觉得没发生过也不穿帮。

理由：用户要的是"当小说看"，而不是"数据触发器合集"。留一个不确定性入口，故事才有生活气。

### 4.4 ⚠️ 第二个关键提案：`gifted` 是白捡的一条线

`item.gifted`（是否转送）/ `item.giftedAt`（转送日期）在 `db.js:103-104` **已经存在，且全项目零使用**。

这是全库唯一一个能让玩家产生**强烈道德震颤**的数据点："这一串，你已经送走了。" T05 建议单独立项，它的剧本强度够撑一整幕，远超一个普通事件。
