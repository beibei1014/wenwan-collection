## 一、一句话主线 + 核心驱动力

### 1.1 一句话主线

> **你是一巷沁灵的引者，你自己也在修行。你只有三次能替人举荐的机会、一年只有一次岁除能公开盘点；这一年谁晋了阶、谁还在巷里、你和谁走到了哪一步——岁除那天挂出来，一眼就能看见。**

### 1.2 核心驱动力：三个人在争什么

| 主体 | 争的东西 | 具体形态 |
|---|---|---|
| **玩家（引者）** | **引位** —— 岁除进境簿上，你和你引的每只各占一行 | 你的四阶修行 + 你这一年替谁做了决定 + 你自己的见证 |
| **巷里的沁灵** | **晋阶与被举荐的资格** | 凝形 → 开窍 → 蜕形 → 化形（`STAGES` 现有 4 阶），以及"今年有没有被举荐" |
| **巷外 · 大巷的引者** | **后辈名额** | 已化形的引者可以为自己的后辈占一个位置。你的人被占，名额就没了 |

**统一的争夺物：一个被记住的位置。**

三条压力同时存在，而且**互不冲突**：

```
前  →  谁晋了阶（横向比：别人比你走远了）
中  →  今年的举荐给谁（你的三次机会）
后  →  大巷的化形引者在抢同一批位置（外部竞争）
```

### 1.3 玩家在主线里是什么角色

玩家不是主人、不是训练员、不是观众。玩家是 **引者**——引者自己也在修行，并且**修行的内容就是"引"**：

| 阶 | 名 | 玩家能做什么 | 玩家阶位带来的门控 |
|---|---|---|---|
| 1 | **识种** | 认出每只是什么型、什么脾气、哪一年入的巷 | 只看得懂「照面 / 眼熟」两只的深浅 |
| 2 | **知时** | 看得出窗口什么时候开、什么时候关 | 能安排引市报名，能用引位 |
| 3 | **借势** | 把别人的机会借过来（跟大巷的人搭上线） | 能举荐别人的串 |
| 4 | **同尘** | 陪它走它自己那一段，不替它决定 | 能替它挡关 |

**门控是这套设计的承重墙**：

- 低阶玩家推不动高档内容 → **不会觉得内容在硬塞**（每卷都能跑）
- 高阶玩家有独有能力 → **照顾 12 只这件事本身变得有难度**（前人做不了后人的活）
- 玩家阶位与沁灵阶位**不同轨**：玩家第 3 阶时，手下可能全是凝形。这不是 bug，这是"引者比被引者先长大"的真实结构。

## 二、世界观补丁（只写卷纲要用到的部分）

>已有的世界观细节见 `docs/v163-世界观与主线设定.md`。本节只补四样卷纲直接依赖的设定，每一条都落到可判定的规则。

### 2.1 岁除（唯一新增的时间制度）

| 项 | 规则 |
|---|---|
| 定义 | 一年里可数的一个日子，**全巷同一天**。代码落点：`ww_story.year`（修行年，360 天为一年），岁除 = 每 360 天一次的结算点 |
| 为何统一 | 岁若是"各自挂瓷周年"就变成一堆日子，**"可数"这件事会失效**，盘点感变成等通知 |
| 它是什么 | 公开的、年度的、**可预期的**。玩家从第1 天就知道还有多少天 |
| ⛔ 它不是什么 | 不是清算日、不是淘汰日、不是截止日。它不结束任何一只的任何事 |

### 2.2 引位（每年三次）

| 项 | 规则 |
|---|---|
| 定义 | 每年只有 **3 次**举荐机会（`NOMINATE_SLOTS = 3`）。一次 = 替一只串在岁除进境簿上提名 |
| 归属 | 归玩家，不归单只。**用掉就没了，明年恢复** |
| 效果 | 被举荐 = 岁除进境簿上多一行 + 大巷的人看见它 + 下一年同类机会更容易拿到 |
| ⛔ 不是什么 | 不是什么保命符。**落选的一年它照样修行、照样晋阶**，只是名字没在榜上 |

### 2.3 大巷（外部竞争者）

| 项 | 规则 |
|---|---|
| 是什么 | 比沁灵巷高一级的引者聚集地。已化形的引者在这里占位置 |
| 他们要什么 | **后辈名额**。他们不为难你，只为先来的人占位——位置满了，你的人就没位置 |
| 为什么是他们 | 纯粹的制度性竞争。**不需要写成反派**，反派化会让故事滑向"对付谁" |
| 他们的手段 | 三种，都合法：抢注名额、许诺更好的引路条件、在你之前把某只接走一次谈 |
| 你能做什么 | 抢注、许诺、或者**用"共同举荐"去换他们的资源**（卷四的核心交易） |

### 2.4 引市（每月一次）

| 项 | 规则 |
|---|---|
| 是什么 | 巷里的集市。每月开一次，外巷的人来，带门的来 |
| 作用 | 它是"被看见"这件事的物理地点。带谁去 = 你今年的资源分配 |
| ⛔ 不是 | 不是抽卡、不是随机事件池。它是**你主动排期的一张表** |

## 三、「玩家帮助修行」的完整设计（本次最重要）

### 3.1 前提核对：帮修行到底能不能加速晋阶

这是用户直接点名要核的数。逐条核完的结论如下。

#### 3.1.1 现有门槛的真实实现

| 项 | 代码事实 | 位置 |
|---|---|---|
| 4 阶 | 凝形 / 开窍 / 蜕形 / 化形 | `spirits.js:650 STAGES` |
| `need` 字段（展示口径） | 0 / 30 / 90 / 180 | `STAGES[].need` |
| **实际判定口径** | `STAGE_DAYS = [0,7,30,120]` ∧ `STAGE_PLAYS = [0,5,20,60]`，**双条件取较慢者** | `spirits.js:725-726` |
| 判定函数 | `stageOf(item, rec, now)` —— 读 `dayNoOf(rec.bornAt)` 与 `item.playCount`，**纯函数** | `spirits.js:728` |
| 能否手动突破 | **不能**。`stageInfo` 里 `canBreak = false` 恒定 | `spirits.js:1139` |
| 进度条 | `stageProgress` / `stageInfo` 均改读 `STAGE_DAYS/STAGE_PLAYS`，`need` 只剩展示 | `spirits.js:740 / 1148` |

#### 3.1.2 核对结论（v4.1 修订：P0 已修，两条结论被改写）

> **🔴 本节在 v4.1 被推翻重写。** 原 C2「4 阶门槛成立，一个数字都不用改」是**错的**——
> 写它的时候我把 `STAGE_DAYS = [0,7,30,120]` 按 index=stage 读了，**没回看它长度够不够**。
> 那个数组长度只有 4，而 `stageOf` 循环到 `k=4`：`STAGE_DAYS[4]` = `undefined`
> → `days >= undefined` = false → `break`。**化形不是"慢"，是永久不可达。**
> 实测：挂瓷 3000 天 / 盘玩 999 次，仍停在 stage 3。
> **这和我在 v164k 那次把 `STAGES[].need` 当成真实门槛读，是同一类错误：读了一个字段就以为懂了。**

**P0 修法（三份文档交叉验证后定案）：补前导占位，不是补后一位。**

```js
const STAGE_DAYS  = [0, 0, 7, 30, 120];   // index 2/3/4 = 开窍/蜕形/化形
const STAGE_PLAYS = [0, 0, 5, 20, 60];
```

| 修法 | 开窍 | 蜕形 | 化形 | 判定 |
|---|---|---|---|---|
| 现状（坏） | 30天/20次 | 120天/60次 | **不可达** | 🔴 |
| 补后一位 | 30天 | 120天 | **240天** | ⛔ 会把开窍砍到 7 天、蜕形砍到 30 天 |
| **补前导占位** | **7天/5次** | **30天/20次** | **120天/60次** | ✅ **定案** |

**三条外部证据**（不是我拍的，是文档已经按它写完了）：
1. `HEAD_COUNT = [0,4,6,8,9]` —— **同文件同约定**：长度 5、首位占位、按阶段号索引
2. 本卷纲 §3.1.1 按 index=stage 读
3. `情感系统设计` §4.2 整张解锁表按它写：`同室=开窍(7天+5)` · `同心=蜕形(30天+20)` · `沁透=化形(120天+60)`

→ **这两个数组本来就该有前导 0，写的时候少了一个。** 所以修法 E 是"补回作者原意"，**不需要任何平衡性讨论**。

**对现有玩家是纯增益**（已实测 8241 样本，掉级 0 例）：`stageOf` 是 `(挂瓷天数, 盘玩次数)` 的纯函数，两个门槛都只变松，已达成阶段不可能掉。已在开窍的玩家修完直接进蜕形——是加速不是回退。

| # | 结论（v4.1） | 依据 |
|---|---|---|
| **C1** | **帮修行在结构上不可能加速晋阶。** | `stageOf` 是纯函数，只有两个输入。天数轴与次数轴**都无加速位**。⚠️ v4.1 起这条**由设计约束升格为事实**：游心流已撤回 `devoteOf += 8`（改 plays）与「天数门槛 −15 天」两条通道 |
| **C2** | **4 阶门槛成立，但需要先修 P0。** | 修好后化形硬绑 `days ≥ 120 ∧ plays ≥ 60`，玩家就算把所有事做到最好也得等第 120 天。**这是"帮再多也不能跳级"的物理保证** |
| **C3** | ⚠️ **`devoteOf` 的准入形式仍有讲究**（不是"要不要"，是"怎么算"） | 游心流已把 `devoteOf` 从「降级关键/P0」降为**待裁决**（他核实 `playCount` 两处自增都不判品种，没有串被锁死）。**但形式必须是 `max()`，绝不能是 `+`** —— 见下 |

> **给架构师的一条硬约束（写进卷纲，因为它约束后续所有代码改动）**：
> **帮修行不得给 `stageOf` 引入「加成」。**
> 判定函数只认两个东西：**过了多少天**、**上手多少次**。两个轴都只能被"替代"满足，⛔ 不能被"加成"满足。
> - ✅ **允许**：`devoteOf = max(playCount, rec.devote)` —— 照料**替代**盘玩满足次数轴，且 `rec.devote` **每天上限 +1**
> - ⛔ **禁止**：`playCount + rec.devote`（加成）、任何写入 `STAGE_DAYS` 的减免、`stage` 手动赋值路径
> - ⛔ **禁止**：`devote` 进天数轴。天数轴是「帮再多也不能跳级」的唯一保证

##### C3 展开：`devoteOf` 怎么算才不产生 guilt

游心流已撤回两条加速通道，并把 `devoteOf` 从 P0 降为待裁决。他的重构是这轮的关键：

> **等价不产生 guilt，加速才会。**

**我同意，并且要把它写死成一个可判定的形式：**

| # | 规则 | 为什么 |
|---|---|---|
| 1 | ✅ **必须是 `max(playCount, rec.devote)`，⛔ 不能是 `playCount + rec.devote`** | `max` = **替代**（照料可以代替盘玩满足门槛）；`+` = **额外**（照料让门槛变松）。**`+` 就是加速，`+` 就制造 guilt** |
| 2 | ✅ **`rec.devote` 每天最多 +1** | 否则一天点 50 次就顶过盘玩一个月，次数轴直接崩 |
| 3 | ✅ **盘玩仍可一天多次（若 UI 支持），照料不可** | **必须保留"愿意动手的人走得更快"这个差异**。完全等价会抹掉选择的意义 |
| 4 | ⛔ **`rec.devote` 不得进 `STAGE_DAYS` 那一半** | 天数轴是「帮再多也不能跳级」的唯一保证，碰它就全线失守 |

**这条设计成立的前提是：`rec.devote` 服务的是「愿意照料但不愿按按钮」的人。**
那个玩家现在的处境是：**他的爱不计数。** 加了 `devoteOf`（`max` 形式）之后，
他的爱开始计数——**这不是加速，是把他的投入从零变成非零。**

⚠️ **但代价也要说清**：加了 `devoteOf`，`stageOf` 就不再是 `(挂瓷天数, 盘玩次数)` 的纯函数了，
C1「结构上不可能加速」这句话要改成「**结构上只能走替代路径，不能走加成路径**」。
**语义变了，别让文档继续说旧话。**

#### 3.1.3 那么"帮"落在哪三个轴上

晋阶**不动**，「帮」因此不能是"催熟"，必须是**别的三件事**：

```
晋阶（0/7/30/120 天 ∧ 0/5/20/60 次）  ← 只有时间和上手能改，帮你改不了
   │
   ├── 路向 route     ← 同阶内它走哪条路      【帮 · 开】
   ├── 举荐 nominate  ← 岁除榜上有没有它      【帮 · 换】
   └── 解锁 open      ← 提前打开这一阶的内容  【帮 · 给】
```

**这三件事加起来才是完整的"我参与了它的修行"**：我决定它成为什么样的存在、我把它推到该被看见的地方、我让它早一点拿到本来会错过的东西。**而它的晋阶仍然只能靠日子。**

### 3.2 帮的三种形式（⛔ 一处都不是物理占有）

**判定标准**（写给所有写手）：如果这个动作可以描述成「你拿着它 / 你收了它 / 你把它带走」，那就是越线了。合法的帮法必须满足**至少一条**：安排场合、替它做决定、指一条路、替它挡一道关。

| # | 帮法 | 玩家做的动作 | 它的动作 | 落点轴 |
|---|---|---|---|---|
| **H1** | **引路 · 替它做决定** | 在岔口替它选 | 它走选中的那条 | `route` |
| **H2** | **引路 · 指一条路** | 给出一个方向，**由它决定走不走** | 它可以拒绝 | `route`（可能不变） |
| **H3** | **挡关 · 替它顶一道** | 消耗自己的 1 次引位，替它挡掉一次关卡失败 | 它自己去闯，你只顶一次 | `举荐`资格 |
| **H4** | **布场 · 安排它被看见** | 花1 次引位给它报名引市 | 它站在那儿，被谁看见 | `举荐` + `route` 修正 |
| **H5** | **共修 · 陪它走它那一段** | 不消耗任何东西，只花时间 | 它自己走 | `解锁` |

⛔ **H1-H5 里没有一条是"你替它修行"。** 修行还是它在修。你做的是**路上的事**：排期、选择、兜底、陪伴。

#### 3.2.1 五种帮法的落点细则

**H1 · 引路 · 替它做决定**
- **场景**：每只在一阶内会碰到岔口——`stage 2` 时一次、`stage 3` 时一次（`stage 4` 起它自己决定）
- **玩家选二选一**，选完 `route` 定下
- 岔口示例（stage 3 的第一次岔口）：
  - 「随队走」→ 稳。进境簿位次中游，但不会缺席
  - 「自己走一趟」→ 快。可能赶上窗口，也可能赶不上（→ 落到「错过窗口」代价）
- ⛔ 注意：**玩家替它选，它同意**。同意这件事本身是一场戏，不是按钮

**H2 · 引路 · 指一条路**
- **和H1 的区别**：H1 你决定，H2 它决定
- **适用**：三种性格会走 H2 —— `aloof`（不接受被安排）、`wild`（自己冲）、`dignified`（要先问它意思）
- **这一条是设计上的关键**：它保证「帮」不等于「控制」。玩家永远有"只能给建议"这一档

**H3 · 挡关 · 替它顶一道**
- **场景**：晋阶关口。每只的 `stage N → N+1` 有一次「过不去就得多等一轮」的时刻
- **玩家消耗 1 次引位**，把它顶过去
- ⛔ **只能顶一次，且不记名**。它不知道是谁顶的（或者知道，但不会说）——这是这条线最好的写法
- **代价**：这一次引位就没了。如果你本来想举荐另一只，你就没了

**H4 · 布场 · 安排它被看见**
- **场景**：引市（每月一次）。带谁去 = 你排的表
- **花 1 次引位**给它报名
- **结果**：它在引市上被谁看见 → 决定它的 `route` 修正 + 举荐概率
- ⛔ 一次引市**能带几只受你自己的阶位门控**（见 §1.3）：识种只能带1 只，知时 3 只，借势及以上 5 只

**H5 · 共修 · 陪它走它那一段**
- **零消耗**，纯时间
- **唯一作用**：解锁内容。这一阶里有些东西只有"你在场"才会出现
- ⛔ 这一条是**情感底色**所在：它不产生任何数值收益，只产生"那一段有人陪"

### 3.3 代价与取舍（⛔ 只有事业线损失，没有一条是失去）

#### 3.3.1 四种代价（全部可复算）

| 代价 | 具体规则 | 可逆？ | 折算 |
|---|---|---|---|
| **① 机会成本** | 每年 3 次引位。用一次就没了 | ✅ 明年恢复 | 今年还能帮 2 只 |
| **② 排名落后** | 进境簿位次 = f(stage, route, 举荐)三因子 | ✅ 明年恢复 | 位次靠后 → 明年同类机会更难拿 |
| **③ 错过窗口** | 举荐窗口 = 到达该阶后 `7×N` 天内有效 | ⛔ **真的等一年** | stage3 窗口 21 天，过期等下一轮岁除 |
| **④ 自身修行** | 玩家晋阶需要**见证**：见证一只晋阶 → 玩家 +1 阶进度 | 部分 | ⛔ **见证窗口只有那一天** |

#### 3.3.2 ④ 才是真正的两难

玩家自己的四阶**只有一条涨法**：见证一只在自己手下晋阶。

```
见证 → 玩家晋阶（4 次见证）
共修 → 玩家进度不动，但解锁它的内容
引位 → 你能帮更多只，但你自己不涨
```

**所以真实的取舍是**：

> 你要把这一次见证，给一只本来就能晋阶的（稳赚），
> 还是给一只**卡在关口上**的（你替它挡关，它才晋得成）？

- 给稳的 → 你自己进这一步，但那只白等一年
- 给卡的 → 它成了，你的进度不变（**见证发生在它晋阶之后，你没赶上**）

**这是纯事业线取舍**：一边是自己的阶，一边是同伴的一年。**没有一个选项是"失去"。**

#### 3.3.3 ⛔ 代价的三条禁令

| # | 禁令 | 为什么 |
|---|---|---|
| 1 | ⛔ 代价里**不得出现**同伴的损失（掉阶 / 受伤 / 不在了） | 任何以同伴福祉为代价的选择，玩家都会拒绝选择它——那不是选择，是惩罚 |
| 2 | ⛔ 代价里**不得出现**玩家的经济损失（花钱 / 花真钱） | 用户明确"不主动触发"任何现实代价；且已有规范禁止让玩家白花钱 |
| 3 | ⛔ 错过窗口**不许写成"来不及了"** | 措辞禁令：只写"今年这一轮过了"，不写"错过了就救不回来" |

### 3.4 「引位」取代 v3 的「带得走几只」

v3 用「亲密度决定带得走几只」，这个设计有个致命问题：**「带不走」暗示「不在场就出事」**，是惩罚关系的残留。v4 换掉它。

| | v3（作废） | v4（引位） |
|---|---|---|
| 稀缺的是什么 | 亲密度（你养了多少） | **引位次数（你今年做了几次决定）** |
| 稀缺的结果 | 你带不走它 | **你今年只能提名3 只** |
| 关系亲疏的角色 | **决定生死资格** ⛔ | **只决定内容深度**：羁绊深 → 岔口那场戏更长、H5 能解锁更多 |
| 「不够」的意思 | 你不够爱它 | **你今年不够用** |

**这一改动的意义**：亲情和资源解耦了。玩家可以**很爱12 只、但今年只能提名3 只**——这是"博爱的人的真实代价"，而不是"你不配"的惩罚。

### 3.5 ⛔「帮不动」的三种设计（这一节是情感核心）

帮得越狠越容易写成万能工具。所以必须有帮不动的：

| # | 帮不动 | 为什么 | 玩家的体验 |
|---|---|---|---|
| 1 | **凝形期（stage 1）帮不了** | 它连岔口都没有 —— `stage 2` 才第一次岔口 | 你只能**带着它**。它跟着你走一整天，一句话也不说，但那一天它在你身边 |
| 2 | **三种性格不接受 H1** | `aloof` 不接受被安排 / `wild` 自己冲 / `dignified` 要先问 | 你只能走**H2 指一条路**，然后接受它可能不选。**它有权拒绝你** |
| 3 | **H3 只能顶一次** | 不记名，且一年内只有 3 次引位 | 你顶了这一次，就没有第二次了。下一只卡在关口上，你只能看着 |

**第3 条最重要**：它保证了「帮」不是无限资源，也让玩家在第 11章（引位用尽的那一章）面对一个真实的、不能靠好感度解决的困境。

## 四、岁除 = 盘点（完整设计）

### 4.1 岁除这天做四件事

| # | 事 | 内容 | 数据落点 |
|---|---|---|---|
| 1 | **晋阶公示** | 这一年谁往上走了，一眼看见 | `ww_story.yearLog` 按 stage 排序 |

### 4.2 残酷感的唯一合法来源：横向比较

>你站在榜前，看见别人比你走远了。**没有人宣判你，只是你自己看见了。**

| ✅ 允许 | ⛔ 禁止 |
|---|---|
| 榜上有人的`stage` 比你高 | 榜上有人的名字被划掉 |
| 你的引位用完了，同行用了 3 次 | 谁"没赶上" |
| 别人今年举荐了 3 只，你举荐了 2 只 | 谁"掉队了" |
| 大巷的人先占了一个位置 | 谁被淘汰 / 谁出局 |

### 4.3 ⛔ 岁除的四条硬禁令（写给所有写手）

| # | 禁令 |
|---|---|
| 1 | ⛔ 岁除前**不得**安排任何一只撑不过去、赶不上、状态不好 |
| 2 | ⛔ 岁除**不做**死线。距岁除 20 天时，UI 不出现任何"你还有 20 天"的施压措辞 |
| 3 | ⛔ 岁除**不得**让任何一只缺席。全册在册的一定都在榜上（落选的也在，标注"今年未举荐"） |
| 4 | ⛔ 岁除**不做**总结、不做回顾独白、不做"这一年就这样过去了"。岁除是**向前看的**，账在卷六 |

### 4.4 岁除的三个场面（每卷末都有一次小岁除）

| 场面 | 规模 | 内容 |
|---|---|---|
| **小岁除**（卷一末 / 卷三末） | 在册 1-10 | 你第一次看见榜；第一次知道"能提名3 只" |
| **中岁除**（卷二末 / 卷四末） | 在册 4-16 | 你开始**知道别人比你走远了**；第一次因为引位不够而必须选择 |
| **大岁除**（卷五末） | 在册 10-24 | 全巷榜。带去的、留下的，**都好好的** |

**三个场面同构、规模不同**。同一个"榜"的信息量一样，**孤独感完全不同**——这就是规模分级在岁除上的落点。

### 4.5 岁除的数据落点

```js
// ww_story新增（全局，不进 rec）
{
  year: 3,                 // 修行年，360 天/年
  nextNominate: 3,         // 今年剩余引位（重置到 3）
  seen: ["c3", "c7"],     // 看过的岁除名册 id

```
⛔ **岁除不产生任何"失去"状态**：不写 `lost`、不改 `stage`、不删 `rec`。**全年唯一的状态变化是 `rec.nominated`（本年被举荐）。**

## 六、规模分级 + 开沁入队

### 6.1 规模分级：人数如何变成不同的矛盾

| 在册 | 巷里的称呼 | 这一档的**矛盾源** | 玩家的实际困境 |
|---|---|---|---|
| **1** | 就它一个 | **孤独**：所有事它一个人扛，且它自己不慌——你才慌 | 你没有参照系。进境簿上只有一行 |
| **2-3** | 两三个 | **不够**：一件事只能派一个去，派谁就得罪另一个 | 引市只能带1 只（识种），另一个在巷里等 |
| **4-6** | 几个 | **分薄**：一个人卡在关口，剩下的人不够替补 | 3 次引位 vs 4-6 只 → **第一次必须排序** |
| **7-12** | 一巷 | **引位不够分**：一年 3 次，一巷要举荐的人 | 你开始**记得住每个人的关口日期**，这很累 |
| **13-24** | 一巷人 | **名次就那样**：榜上就那么几个名字在前 | 你照顾不过来——**这不是惩罚，是你只有两只手** |

> **这张表就是「人手不够」的设计。** 队伍小不是弱，是另一种难。所以主线在任何规模下都能跑，只是内容不同，**不需要挂满 24 只才能玩主线**。

### 6.2 开沁入队：每只新来的必须带一次争论进来

**通则（整个扩员机制的引擎）：**

> **每一只新挂瓷的沁灵入队时，必须在它入队的那一卷，制造一次「今年这三次引位给它」的争论。**

这样扩员就是**剧情引擎**，不是「人数 +1」：

| 新来的是什么型 | 它带来什么 | 它制造什么矛盾 |
|---|---|---|
| `cool` / `aloof` | 办事利落、不废话 | 直接跟现有的争引位 → **内部竞争** |
| `mystery` / `pampered` | 知道别人不知道的事 | 解锁一段信息，**但它只说一半** → 逼你选信不信 |
| `gentle` / `sweet` / `sentimental` | 会照顾人，队伍情绪稳 | 大家开始依赖它 → **依赖是危险品**：它一旦卡在关口，全巷的排序都要重排 |
| `heroic` / `wild` / `wanderer` | 能冲、能挡 | 它要往前冲 → 你要不要把引位压在它身上 |
| `scholar` / `dignified` / `calm` | 懂规矩、能算窗口 | 它会告诉你「这样做不合规矩」→ 规矩和活路冲突 |
| `lively` / `cheeky` | 消息灵通、气氛好 | 藏不住事 → **它把不该说的说了**（谁的窗口快关了，它在引市上喊出来了） |
| **刚挂瓷没几天的新生**（stage 1） | 它什么都不会 | **「它连岔口都没有，你今年就为它花引位？」**——这是伦理困境，不是选择题 |

**最后一行是我特意留的**：一只还没成长的小家伙，成了队伍里最沉的那个问号。这一条让「人多」变成负担，而不只是爽点。

### 6.3 渐进扩员的机制事实（已核代码）

| 事实 | 依据 |
|---|---|
| `PLAYABLE_CATS = ["菩提"]` —— **盘玩只对菩提生效** | `app.js:77` |
| 阶段由「挂瓷后天数 ∧ 盘玩次数」双条件派生 | `spirits.js:725-726` |
| 沁灵在**挂瓷那一刻**诞生（`born()`掷性别、记里程碑） | 现有实现 |
| `mainSetOf` 是**主串集**（手动勾选 + 5 星自动 + 开沁最早兜底），O(n) 单遍 | `spirits.js:4109` |

**所以扩员是字面意义上的**：玩家挂瓷一只，巷里就多一个人。节奏在玩家手上。

## 七、12 只各自扮演什么角色

### 7.1 分配原则

⛔ **不许用胎性/材质做性格差异**（用户只有菩提根会盘玩，胎性对其余全是空转）。差异化**只允许**建立在真实存在的东西上：

```
角色定位 = 15型人格（rec.look.pers）
        × 修行阶段（STAGES）
        × 玩家亲笔写的设定（rec.look.persona）
        × 它在主线里的功能位
```

**「功能位」是什么**：不是性格标签，是**它在群像里干的活**。12 只各有各的活，所以 12 只在场时，场面本身就是可读的。

### 7.2 12 只 · 功能位表

| # | 人格 | 它的功能位 | 它在群像里干什么 | 它跟玩家的核心张力 |
|---|---|---|---|---|
| 1 | `gentle` 温柔安静 | **守夜人** | 替全巷等门、记谁今天没回来 | 它照顾所有人，**没人照顾它** |
| 2 | `lively` 活泼元气 | **信使** | 跑腿、传消息、把引市的消息带回来 | ⛔ 它藏不住事（第 6-2 条争论的来源） |
| 3 | `cool` 高冷傲娇 | **挡关者** | 关口上第一个上 | 它不好管，但**它在的时候你敢闯** |
| 4 | `calm` 沉稳可靠 | **账房** | 算窗口、排引市表、记引位余额 | 它什么都记得，所以**你不能忘** |
| 5 | `mystery` 神秘慵懒 | **知情者** | 知道巷外的事，但只说一半 | 逼你选信不信 |
| 6 | `scholar` 温润书卷 | **规矩人** | 会说"这样做不合规矩" | 规矩和活路冲突时，它是你唯一的说真话的人 |
| 7 | `aloof` 清冷疏离 | **裁判** | 不参与争，但它的判断常被采纳 | ⛔ **它永远走 H2**（不接受你安排） |
| 8 | `sweet` 娇憨可爱 | **被护者** | youngest one，全巷都护着它 | ⛔ 它连岔口都没有（第 6.2 伦理困境行） |
| 9 | `wanderer` 洒脱江湖 | **远征者** | 要往外走、要看更远的地方 | 你要不要把引位压在它身上 |
| 10 | `heroic` 侠气凛然 | **前锋** | 挡在前面，冲动 | 它要往前冲，你得决定让不让 |
| 11 | `dignified` 端方持重 | **门面** | 对外的代表，站得住 | ⛔ 它也要先问它意思才肯走 |
| 12 | `wild` 野性未驯 | **难驯者** | 不听安排，最难帮 | ⛔ **它永远走 H2**，且经常自己冲出去 |

**未占用的 3 型**：`cheeky` 古灵精怪、`pampered` 慵懒富贵、`sentimental` 多愁善感。
→ **替补方案**：这3 型的功能位与上表第 2（信使）、第 5（知情者）、第 11（门面）**互换或并存**。写手按实际挂瓷的人格取用，**人格 → 功能位的映射是 O(1) 查表，不做两两枚举**。

### 7.3 同人格在不同卷的行动差异（关键设计）

⛔ **同一个人格在五卷里必须做不同的事。** 这是"12 只不是 12 份拷贝"的落点。

以 4 只为例：

| 人格 | 卷一 · 识 | 卷二 · 同行 | 卷三 · 引位 | 卷四 · 各行 | 卷五 · 岁除 |
|---|---|---|---|---|---|
| `gentle`<br>守夜人 | 它只等你一只。巷里没别人 | 它开始记别人的名字 | **它成了排队表本身** —— 谁在等它先说 | 它记不住了，因为人太多了 | 它终于把所有人都等回来了 |
| `cool`<br>挡关者 | 谁都不理，只对你有反应 | 它第一个上关口，但**不让你花钱** | 它替你挡下「你自己得罪人」的那件事 | 它有了自己的 `route`，不再是你的工具 | 榜上念到它名字时，它是**唯一没反应的那个** |
| `scholar`<br>规矩人 | 它告诉你「这样做不合规矩」 | 它第一次**破一次规矩**（为了帮你挡关） | 它开始给全巷立规矩 | 它发现规矩不如活路，**自己撕了自己写的** | 它把这一年抄成了一本册子 |
| `wild`<br>难驯者 | ⛔ 完全不配合 | 它自己冲了一次，你没拦住 | 它冲出去**替全巷**挡了一次 | 它有了同伴（`heroic`），**第一次不是一个人冲** | 它带回来一样东西，谁也不知道它从哪弄的 |

**规律（写手的规矩）**：

1. 同人格在每卷的**功能位不能相同**，但**性格底色必须一致**（`scholar` 到哪卷都是读书人的底子）
2. 差异体现在**它面对的人变了**——卷一只面对你，卷三面对一巷，卷五面对大巷
3. ⛔ **不许用「它变坏了/它变了」写差异**。同一个人格是同一个人，只是处境不同

## 八、情感线怎么接（主线不恋爱向，但要有亲密张力）

### 8.1 三条铁律

| # | 铁律 |
|---|---|
| 1 | **主线的冲突永远是修行与位置。** 任何一场戏如果去掉「修行/位置」这层就仍然成立，那它就不该在主线里 |
| 2 | **亲密张力靠「它在你面前的样子」和「你看见别人也看见它」制造**，不靠告白、不靠身体接触 |
| 3 | ⛔ **主线不出现恋爱向台词。** 恋爱向内容由 `docs/v164l-情感系统设计.md` 的三层锁（羁绊 ≥ 相知 ∧ stage ≥ 4 ∧ 玩家显式确认）在**主线之外**承接 |

### 8.2 亲密张力的四种来源（都在主线之内）

| # | 来源 | 怎么写 | 典型章 |
|---|---|---|---|
| **① 被看见的耻感** | 它在引市上被陌生人看，它回来一句话不说 | ⛔ 不写脸红，写沉默与躲。**张力比表白强** | 第 13、22 章 |
| **② 被优先的负担** | 你把引位给了它，没给另一只 | 它**不知道**，另一只**知道** | 第 11、15 章 |
| **③ 它拒绝你** | 你替它选了，它没选 | ⛔ 它不给理由。**它有权不给** | 第 6 章 |
| **④ 它长大了你看不下手** | 凝形 4 头身 → 化形成人，你抱不动了 | 它站起来比你高半个头。**你伸手，它已经不需要了** | 第 19、23 章 |

### 8.3 ⛔ 形态红线（硬约束，非风格偏好）

代码里`STAGES` 明写：`凝形=4头身婴儿`、`开窍=6头身小孩`、`蜕形=8头身少年`。

| 内容 | stage 要求 | 尺度 |
|---|---|---|
| 家人向 / 群像向 | **全阶段可写** | 照顾、等门、留灯、记名字 |
| 亲密张力（非恋爱） | `stage ≥ 3`（8 头身少年） | 心理距离的描写，不写身体 |
| ⛔ 恋爱向 | `stage ≥ 4`（化形成人）**且不在主线内** | 见情感系统设计 §4.3 |

**这条不是束缚，它给了主线一个天然的庄重结构**：它站起来那天，你伸手，然后收回手。

### 8.4 家人般的底色怎么落地

「家人般的依恋与照顾」在主线里的落点是**分工，不是台词**：

| 分工 | 谁干 | 体现在哪 |
|---|---|---|
| 记谁在等 | `calm` 账房 | 第 10、22 章的引市排期表 |
| 守门等人 | `gentle` 守夜人 | 第 17、21 章 |
| 说真话 | `scholar` 规矩人 | 第 14、18 章 |
| 替别人挡 | `cool` + `heroic` | 第 7、19 章 |
| 外面带回消息 | `lively` + `wanderer` | 第 13、23 章 |

**这五件事凑齐了，巷子就是一个家。** ⛔ 而这个家的所有台词都是**修行路上的事**——它不是"我们是一家人"的宣言，是"谁今天该轮到你了"的排期。

## 十三、支线三触发口与主线的接缝

⛔ 支线**不与主线抢戏**：支线是**一串的私事**，主线是**一巷的公事**。支线永不改变主线进度。

| 触发口 | 挂载点 | 落点 | ⛔ 边界 |
|---|---|---|---|
| **① 单串相关** | `rec` 已有：`events` / `talk` / 夜话 / 房间剧情 | 单只的日常与心事 | 不得推进 `ww_story.plot`；不得消耗引位 |
| **② 某种性格的串加入后触发** | `when.pers`（`WHEN_KEYS` 已有 `pers` 键，读 `e.persSet`） | 某型人格特有的一段心事 | 走 `chapVisibleChoices` 的退路逻辑：**全被过滤时退回全给，绝不卡死** |
| **③ 主线某个选项触发** | ⛔ **不进 `rec.marks`**（K2 字典序） | 主线选项同时种下一个只在支线读的标记 | 标记写 `rec.routeLog` 或 `ww_story.plot.seeds`，**⛔ 不写 `rec.marks`** |

**边界三原则**：

| # | 原则 |
|---|---|
| 1 | 支线**不改** `stage`、**不花**引位、**不动** `ww_story.plot` |
| 2 | 支线的分歧**必须在同一条主线后**才可见（不能超前剧透主线决定） |
| 3 | 支线**永远有一个兜底结局**——条件不满足时走"没有触发"，⛔ 不显示空白、不报错 |

## 十四、自评

### 14.1 这份卷纲读起来像不像一部有意思的修仙冒险群像故事

**我认为「主线」这一层是成立的，「冒险」这一层是我最没把握的。**

主线这一层有一个真实的结构在撑着：**玩家自己的修行只能靠见证涨，而见证窗口只有那一天**。于是玩家面对的每一只，都是同一个问题的变体——

> 我把这一次见证，给一只本来就能晋阶的（我赚一阶，它白等一年），
> 还是给一只卡在关口上的（它成了，我不涨）。

这不是善恶选择，是**只有两只手**的真实困境。而且它落在**一个玩家完全能算清的数字上**（每年 3 次引位）。这比"你会失去什么"耐读得多，因为它是可持续的——玩家每一年都会重新面对一次，而不是被吓一次。

群像这一层，§7.3 那张"同人格跨卷差异"表是我最满意的部分。同一个 `scholar`，卷三开始给全巷立规矩，卷四发现自己写的规矩不如活路、**自己撕了自己写的**——这不是角色变化，是处境变化，所以它不消耗角色。而「守夜人 `gentle` 从只等你一只，到记不住所有人的名字，到终于把所有人都等回来了」，这一条线落下来的时候，一巷人是真的。

**岁除那一场**，按设计它是纯横向的：没有人宣判你，只是你自己看见了。这个设计的好处是它**不需要任何人消失**，所以它可以年年过。

### 14.2 我最没把握的一处

**卷三第 11 章「三次用完了」—— 我不确定它在规模小的时候还成不成立。**

这一章的全部重量压在"引位不够分"上。如果玩家只有 4 只，它就变成"3 次机会给 4 只，很难吗"——**根本不算困境**。我给的兜底是"它值不值得"（把引位给它，你今年的正事就办不成了），但这在 4 只的规模下是个**弱理由**。

而且我把它设成"不自动扣引位、只做既成事实"（Q5），这让这一章的高潮更靠后、更弱。

**要么它得改造成一个在低规模下也成立的结构**（比如把它改成"你要为谁挡关"的取舍，而不是"引位不够"）；
**要么它得在卷一就明确告知玩家这条线的规模前提**，让玩家知道"你现在只有 4 只，这一章对你还不是问题——等你到 7 只以上，它才真正开始咬你"。

我倾向后者：**把它明确定位成"给 7 只以上玩家的第一道真门槛"**，并在小规模时换成一个替代场景（第 11 章的位置给小规模玩家一场别的戏）。但这条我没有把握，需要你定 Q2 之后才能定。
