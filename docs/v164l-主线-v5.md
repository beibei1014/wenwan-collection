## 一、阶段门槛（已落代码，v5 起以此为唯一口径）

### 1.1 现行实现（`spirits.js` 实测，非推测）

```js
const STAGE_DAYS  = [0, 0,  7, 30,  0];   // [4]=0 → 化形不设天数门槛
const STAGE_PLAYS = [0, 0,  2,  5, 10];
const HEAD_COUNT  = [0, 4,  6,  8,  9];

const playsEff = Math.min(plays, days);    // 次数地板
const dOk = STAGE_DAYS[k] > 0 && days >= STAGE_DAYS[k];
if (dOk || playsEff >= STAGE_PLAYS[k]) s = k; else break;
```

### 1.2 四阶门槛表

| 阶 | 天数条件 | 次数条件 | **实际可达**（受次数地板约束） |
|---|---|---|---|
| **凝形** | 起点 | — | 挂瓷当天 |
| **开窍** | ≥ 7 天 | ≥ 2 次 | **7 天**，或 **2 天 + 2 次** |
| **蜕形** | ≥ 30 天 | ≥ 5 次 | **30 天**，或 **5 天 + 5 次** |
| **化形** | ⛔ 不设 | ≥ 10 次 | **10 天 + 10 次**（`playsEff` 把它锁死在第 10 天） |

> ⚠️ **「化形不设天数门槛」不等于「化形很快」。** `playsEff = Math.min(plays, days)` 这一条把天数重新锁回来了：
> `min(plays, days) ≥ 10` **必须同时满足** plays ≥ 10 且 days ≥ 10。
> **化形实际门槛 = 挂瓷 10 天 + 盘玩 10 次。**
> 这一条堵的是「6 天狂点 99 次跳阶」的漏洞（v164m 引入），**它同时也是 26 章长线门槛失效的根因**（见 §三）。

### 1.3 替换 v4 的旧数字

v4 §5.2 逐章表里凡按 `stage≥N` 做门槛的章，**其门槛已全部失效**（化形 10 天可达）：

| 章 | v4 原门槛 | v5 改为 |
|---|---|---|
| 5《第一次岔口》 | `stage≥2` | `days≥30`（或玩家阶位≥知时） |
| 7《挡关》 | `stage≥3` | `days≥45`（或玩家阶位≥借势） |
| 16《各自的道》 | `stage≥3` | `days≥90` |
| 19《一个人的关口》 | `stage≥4` | `days≥120` |

**理由**：化形只要 10 天，`stage≥4` 不再是任何长线约束。**替掉它的必须是 `days` 或玩家四阶。**

## 二、帮修行三轴：一律不进阶段判定（删净 `devoteOf`）

### 2.1 硬约束（v5 起措辞以此为准）

> **`stageOf(days, plays)` 只读两个自然量：过了多少天、上手多少次。**
> **任何陪伴 / 照料 / 送礼 / 亲密剧情 / 帮修行，都不得影响阶段判定。**
> 帮修行只走内容轴：`route`（路向）· `nominate`（举荐）· `open`（解锁）。

### 2.2 `devoteOf` 已整节删除

v4 §3.1.2 C3 那四条规则（「✅ 允许 `max(playCount, rec.devote)`」等）**已随游心流撤回而作废**。

**⛔ 任何地方都不得复活「允许替代 / 允许照料折算」的说法。** 那是唯一被明令禁止过的形态，因为：
> `max` 看起来是「替代」，但它已经把 `stageOf` 从纯函数变成了「可以被人情影响」的函数。
> 一旦成立，**"它慢了"就有了第二个原因**，而那个原因是玩家自己造成的——那和"系统主动施压"是同一件事。

**`rec.devote` 若保留，只能进羁绊与内容解锁，不得进任何阶段判定。**

## 三、⚠️ 节奏事故预警（必须在写完 26 章前解决）

### 3.1 问题

**化形从 120 天变成 10 天。** v4 的 26 章如果沿用任何以 `stage` 为主轴的长线门槛，结果是：

> **前 10 天解锁到第四章，30 天解锁到第十章——26 章会在一个多月内全部打完。**

**这正是主理人两轮前让我修掉的那个事故**（上一版是「前 9 章 23 天放完，然后空窗 135 天」，我把它拆成五卷并重排了门槛）。**这次是它的镜像：不是空窗，是赶集。**

### 3.2 根因

`stage` 原本同时承担了**两个语义**：
1. **能力位**（能不能上场、能不能自己决定路向）
2. **长线时钟**（要走多久才配得上结局）

新的 OR 门槛把第 2 个语义压垮了。**化形是"成年"，不是"毕业"。**

### 3.3 解决方向（v4 已有可用资源，不需新机制）

**长线时钟改挂在这三样上，它们都不受 `stage` 影响：**

| 资源 | 语义 | 为什么不冲突 |
|---|---|---|
| **玩家四阶**（识种 → 知时 → 借势 → 同尘） | 玩家自己的修行进度，**只涨「见证」** | 它涨得很慢（一年一次岁除才有一个见证窗口），天然是长线 |
| **`days` 陪伴天数** | 陪伴的物理时长 | 玩家不能加速，只能过 |
| **岁除** | 一年一次的公开盘点 | 年度节奏，天然是长线 |

**三样都是「必须花时间才能拿到」，而 `stage` 现在是「认真盘十次就能拿到」。**

### 3.4 由此产生的一条叙事收获（不是补丁，是更好的设计）

> **化形 ≠ 登名。化形是「能上场」，登名是「被记住」。**

这条把 v4 的两个东西接上了：
- **化形（10 天）** = 成年 → 可以进引市、可以走岔口、可以说"我不同意"
- **登名（岁除，一年一次）** = 被世界承认 → **只有这一天才算数**

于是 v4 §3.3.2 那个两难**自动成立且有了正确的时点**：

> 见证窗口 = 岁除那一天。**因为岁除是唯一"被承认"的日子。**
> 你要把这一次见证，给一只本来就能登名的（稳赚一阶），
> 还是给一只**卡在关口上**的（你替它挡关，它才登得成）？

**若登名可以随时发生，见证窗口就没有稀缺性，两难就退化成一个按钮。**
所以「登名一年一次」不只是设定，**它是让 v4 那个两难成立的支点**。
