## 二、用户原始需求（逐条，不可打折）

> 你记得多写一些有趣的故事，串都成精了就不要局限在盘亮，裂了等等这样和串有关的主题上，可以有一个宏大的世界观，现代+中式修仙/玄幻那样的？然后故事就要跟串的形象，性格等等相关，还要跟串和我的亲密度（比如我盘的次数，串陪伴我的天数等）相关，故事可以层层递进，我当小说来看的，你就要把故事想的更完整，更有意思，跌宕起伏。重点的剧情可以生成CG图（根据剧情生成，费用管够），对可以有个地方是收集展示CG的，比如在夜话那个界面，像手机一样增加一个相册。然后你给这些精灵改个名字，文艺一点的统称，不要叫什么挂瓷精灵太直白太土了，要贴合文玩化形的感觉，改了过后整个APP里面对精灵的统称都要统一。

拆解为 6 个交付项（D1~D6）：

- **D1 世界观**：现代 + 中式修仙/玄幻的宏大设定
- **D2 命名统一**：文艺统称，全 APP 替换（用户点名嫌「挂瓷精灵」太直白太土）
- **D3 长线叙事**：层层递进、跌宕起伏、能当小说看的主线
- **D4 个性化**：故事与形象、性格、亲密度（盘玩次数/陪伴天数）挂钩
- **D5 CG 生成**：重点剧情出图，费用管够
- **D6 CG 相册**：夜话界面里像手机相册一样收集展示

## 三、硬约束（所有成员必须遵守，违反即废稿）

### 3.1 规模约束：100+ 只串

- **绝不枚举两两组合 / 全排列 / 全列举**。100 只 = 4950 对，这条路会炸。
  一律只做 **O(n) 扫描**。
- 列表、头像组、badge 一律折叠：画前 N 个 +「+M」。
- 故事必须靠**变量注入 + 条件触发**复用，**不能**给每只串单独写剧情。

### 3.2 成本约束

- 现有剧情**全本地 0 出图 0 模型调用**（v160/v161/v162 都是写死剧本 + 分支状态机）。
- **禁止设计任何「AI 实时生成对话」的方案。**
- **CG 是唯一花钱点**，且用户说费用管够 —— 但仍要控制张数（主线 6~8 张），
  且必须**用户确认才出图**（沿用节令 CG 的 confirmModal 模式）。

### 3.3 风格约束

- **中国古风是硬约束**：禁日式元素、禁西式现代服装。
- 修仙/玄幻设定必须是**中式**（禁用「魔法」「精灵族」「勇者」这类西幻词）。

### 3.4 数据约束

- 跨手机同步走 **整库一行 JSON**（`ww_spirits`），单只串的记录体积要能瘦身。
- 新增字段必须能进 `pruneForQuota` 的瘦身范围，否则会撑爆同步。

### 5.2 命名：主理人裁决「沁灵」（文案策划首推「灵犀」已被用户否决）

用户原话：「不能叫灵犀！！！！！换个名字！！！！！」

**裁决理由**：
1. 「心有灵犀」是**情诗**，甜而黏，且主语是"两个人之间的感应"，而文玩成精的主语是**物**。
2. 「沁色」是**文玩行话**（外来物质沿裂隙渗入玉体形成的颜色变化）。**沁灵 = 沁进去的灵**。整个盘玩行为本质就是"沁"：汗、油、温度、时间一层层沁进死物——与世界观核心「人心久注，器物生灵」是同一个字。
3. 沁灵是**动作不是状态**（自带"正在渗入"的进行时）；灵犀/琳琅/岁华都是静态名词。
4. 通名三连测全过：一只沁灵 ✓ / 这些沁灵 ✓ / 我的沁灵们 ✓。两字、无生僻、输入法零门槛。

**配套命名（待文案策划最终确认）**：量词「尊」· 诞生动作「开沁」· 形态 4 阶「凝形→开窍→蜕形→化形」· 亲密度 6 档「照面→眼熟→相熟→通意→同心→沁透」

### 5.3 世界观核心（一稿通过）

> **人心久注，器物生灵。** 文玩是被"养"的——人把体温、时间、注意力一层层"沁"进一件死物里，沁够了它就醒了；醒了之后它才发现，**养它的那个人，才是它会消失的原因**。

- **为什么偏偏是文玩**：碗盛饭、车代步，人用的是**用处**；唯独文玩，人摩挲它**没有任何用处**。盘玩是人类唯一一种"以改变一个物件本身为目的"的长期行为。
- **包浆就是修为**：挂瓷=灵气初聚 / 沁色=灵气入体 / **包浆=修为小成** / 玉化=化形（不归路）/ **石心=终点**。金句：**"包浆不是脏，是它活过的年头。"**
- **三层威胁**：退形（你忘了它）→ 扫尘人（收旧物者，衬红布铅盒，朱砂封条，**他们认为自己在打扫**）→ **石心**（"它成了。成了，就不说话了。"）
- **石心反转（全书的魂，一字不改）**：**玩家一直在做的那件事，就是杀死它的那件事**。终章必须让玩家主动停止"盘"这个核心动作，才能留住它。

### 5.4 🔴 主理人算出的时间账事故（已转互动设计师）

公式：`bond` 每天 +2、每盘 1 次 +1；`growth = plays*3 + days`（spirits.js:443）

| 章 | 瓶颈 | 耗时 |
|---|---|---|
| 5 窗外有人 | days≥30 | 30 天 |
| **10 夜归** | **days≥180** | **180 天** |
| **11 石心** | **plays≥120** | **120 天** ← 比第 10 章快，**倒挂** |
| **12 终章** | **days≥365** | **365 天** ← 结局要等一整年 |

三个事故：①终章等 365 天，第 11 章的恐惧无法被第 12 章及时消解，情绪链断裂；②第 10/11 章门槛倒挂，后章先开；③老用户 `首次 bond = min(40, days)` 见面礼会让前 9 章同日全开，"层层递进"在第一秒崩塌。
