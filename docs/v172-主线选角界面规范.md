## 0. 一句话结论 & 四条硬约束

**结论**：在 `#/main` 顶部放一张「点戏」入口卡 → 进**独立页 `#/maincast`**；**固定 7 行行当**，每行「行当名（可带朱印 / 可带「家里顶的」徽标）+ 一句位置说明（编剧定稿，⛔ 一字不改）+ 一个自绘下拉（带缩略图）+ 手动态才有的小叉」；底部两个按钮「按在册顺序 · 把没点的都点上」/「按交情重新点一遍」。全部用现有 CSS 变量，浅/深主题都不额外写色。
**每行三种身份**：**手动**（我点的，**朱印 + 小叉，无字**）· **自动**（系统按亲密度配的，**徽标「家里顶的」，无印无叉**）· **暂由人顶着**（无人可派，轮转复用，**同上徽标**，⛔ 不显示成已指派）。
> 🔒 **朱印与徽标互斥**：同一行**要么**朱印 + 小叉（手动）**要么**「家里顶的」（自动 / 顶着），⛔ 绝不同时出现（§2.7）。

| # | 硬约束（已核代码） | 对设计的影响 |
|---|---|---|
| 1 | **行当固定 7 个**（`CHAP_CAST_CFG.MAIN` 顺序，`CHAP_CAST_NAME` 定名，主理人已实测定稿） | 就画 **7 行**，顺序固定（见 §2.0）。⛔ 不再"5~12 自适应"，也不再留 `{角色槽位A}` 占位 |
| 2 | **沁灵数量不定**（新用户可能只有 1~2 只，行当却有 7 个） | ⇒ ① 必须允许**一只沁灵扮多个行当**（代码已有 `fill:true` 语义，一致）② 必须有**「暂由人顶着」态**——代码现在是轮转复用顶上，⛔ UI 不许把它显示成"已指派" ③ 必须有**整体空态说法**（§3.4） |

> ⚠️ `门客·数人的`（剧本 `who` 里出现过）**不在** `CHAP_CAST_NAME` 里 ⇒ 大概率非我方行当，**⛔ 不进这一页**。7 行之外若以后真要加，再走改 `MAIN` + 本规范同步。

## 1. 页面定位与进入方式

### 1.1 判断：**独立页 `#/maincast` + `#/main` 顶部常驻入口卡**（不做弹层、不做页内区块）

| 方案 | 结论 | 理由 |
|---|---|---|
| A. `#/main` 页内常驻区块 | ❌ | 7 行 ×（说明 + 下拉 + 缩略图）会把章节列表整段挤出首屏；且下拉面板在长列表里定位/滚动很难受 |
| B. **独立页 `#/maincast`** | ✅ **采用** | 一屏一事；返回走既有 `#topbar` 的 `#btnBack`（`btnBack` 在 `#/main` 已是 visible，天然一致）；中途改选角随时可进 |
| C. 首次进入引导弹层 | ❌ 不采用 | 窄屏弹层内滚动 + 关闭后不可复访；玩家第一次未必想决策。**改为**：入口卡在「还没点过人」时变醒目 + 带角标「还没点戏」，不强制 |

**入口卡位置**：`#/main` 里，紧跟 `.main-head` → `.chap-prog` 之后、`.chap-list` 之前。
理由：进度条回答「我读到哪」，点戏回答「谁来演」，都属**开演前的准备**；放在章节列表之前，不打断「点章节」的主动线。

### 1.2 入口卡的三种形态（**按"手动指定了几位"判断**，不是按"有没有人演"）

> ⚠️ 因为代码始终会用轮转复用把 7 个行当填满，"有人演"恒为真 ⇒ 入口卡**不能**用"有没有空位"判断，必须用"**手动点了几位**"。

| 状态 | 视觉 | 文案 |
|---|---|---|
| 7 位全手动 | 常态卡，`--card` 底 | 「点戏 · 谁扮谁」＋副行「七位都是你点的」 |
| 点过一部分 | 常态卡 | 「点戏 · 谁扮谁」＋副行「已点 N 位 · 其余按交情」 |
| 一位都没点过 | 卡描边改 `--gold`，右侧角标 | 「点戏 · 谁扮谁」＋副行「七位都还按交情抽」＋角标「还没点戏」 |

### 1.3 ✅ 已裁定：**全局立刻重算**（不搞按章快照）

现状：`castOf(opts)`（`spirits.js:7085`）把出场表缓存进 `ww_story.cast` + `castYear`，**同一年内不重抽**；玩家改选角 = 需要 `castOf({force:true})` 重算。

- **裁定：全局生效，立刻重算。** 理由：剧本里的 `who` 是**抽象行当名**，回放时立绘/头像由 `cast` 现算；若给旧章保留旧 cast，同一个「最老的那只」在第 2 章和第 7 章会长得不一样 —— 比「换了人」更出戏。
- **主理人已接受的代价**：玩家重看旧章，人会跟着换成新指派的沁灵。
- ⛔ **按章快照本轮不做**（每章存一份 cast ⇒ `ww_story.cast` 改结构 + `mainCastThumb` / `portrait` 带章号取值），已明确"成本太高，另立项"。
- 改完必须给玩家一句提示（Toast 见 §3.1）。

### 2.2 下拉框 —— 结论：**自绘面板**（不用原生 `<select>`）

| 理由 | 说明 |
|---|---|
| ① 原生 `<option>` **放不进缩略图** | 各端都不支持在 option 里渲染 `spiritThumbHtml`，最多纯文本 —— 而「认出是哪只串」正是这个页面的全部意义 |
| ② 移动端原生 select 是**系统弹层** | 样式/圆角/字体全不可控，一把把玩家拽出古风调性 |
| ③ 需要状态标记 | 「还扮着别处」「正在扮这位」要打标，原生做不到 |

**折中做法（推荐）**：页面上保留一个**视觉隐藏**的原生 `<select>`（表单语义 + 键盘/读屏可及），可见层是自绘按钮 + 面板。⛔ 不要只留自绘不管无障碍：面板加 `role="dialog"`、列表 `role="listbox"`、选项 `role="option"` + `aria-selected`。

### 2.4 一行的三种身份（**核心**：手动 / 自动 / 暂由人顶着）

| 身份 | 含义 | 类名 | 触发器显示 | 行当名 | 朱印 | 小叉 | 徽标「家里顶的」 |
|---|---|---|---|---|---|---|---|
| **手动** | 玩家自己点的 | `.is-picked` | 缩略图 + 名 | `--text` 16px | ✅ 有 | ✅ 有 | ⛔ **无**（互斥） |
| **自动** | 没手动点，系统按亲密度抽的 | `.is-auto` | 缩略图 + 名 | `--wood-2` 16px | ⛔ 无 | ⛔ 无 | ✅ **有**（11px） |
| **暂由人顶着** | 该行当当前**无人可派**（玩家不足 7 只 / 都被点走），代码轮转复用顶上 | `.is-fill` | 缩略图 **opacity .55** + 名 | `--wood-2` | ⛔ 无 | ⛔ 无 | ✅ **有**（11px） |
| （兜底）**真空** | 极端情况一个都排不出 | `.is-empty` | 36px 虚线圈 + `＋`，文字「还没点 · 点一只」 | `--wood-2` | ⛔ 无 | ⛔ 无 | ⛔ 无（连顶的人都没有） |

- ⛔ **`.is-fill` 绝不能显示成"已指派"** —— 它是"还没点，家里先顶着"，半透明 + 徽标 + 一句说明（下条）；
- 三种身份的**差异不靠单一颜色**：朱印（形状）+ 徽标（有字）+ 字色（明度）+ 半透明（有无）四条线索叠加，色弱玩家也能分辨；
- 🔒 **互斥断言**：`.cast-seal` / `.cast-unset` 只在 `.is-picked` 渲染，`.cast-auto-tag` 只在 `.is-auto` / `.is-fill` 渲染；CSS 再加一层兜底（见 §2.7），双保险。

`.is-fill` 行的下方小字（**定稿文案，⛔ 一字不改**）：

> **还没点，这位是家里自己顶的。**

（14 字 · 12.5px · `--wood-2` · 与触发器内 `opacity:.55` 的头像配套；⛔ 不写"暂且没人 / 顶替 / 无人可用"——头像 + 名字明明在，说"没人"自相矛盾。）

### 2.5 已指派显示在触发器里

- 触发器内就是**被选沁灵的缩略图 + 名字**（所以"下拉框旁显示缩略图"这条自然满足，不用额外放头像）；
- 已读章节页沿用同一份 cast（见 §1.3，改完**全局立刻重算**）。

### 2.6 冲突：**同一只沁灵扮两个行当** —— 主理人裁定：**允许，只提示**

| 方案 | 结论 |
|---|---|
| ❌ 禁止（选过即禁用） | 新用户只有 1~2 只沁灵时**直接开不了局**，与 `fill:true` 语义冲突 |
| ✅ **允许 + 明确提示** | **已裁定**。与代码既有 `fill` 一致；提示用**暖色不是红色**（这是"也不是不行"，不是错误） |

提示文案（行下方小字）：「这一位还扮着「最吵的那只」—— 一个人扮两个，也不是不行。」
视觉：`color-mix(in srgb, var(--gold) 14%, var(--card))` 底 + `--text` 字，行加 `.is-conflict`。⛔ 不用 `--red`（红色在此语境 = 错误，会吓到人）。

### 2.7 「我点的」vs「系统配的」—— ✅ 定案：双线索**互斥**，只有自动侧写字

> 主理人裁定：两侧都要有线索，但**只有一侧写字**；两条线索**互斥、不会同时出现在一行**。

| 线索 | **手动** `.is-picked` | **自动** `.is-auto` / **顶着** `.is-fill` |
|---|---|---|
| ① **朱印**（形状线索，仅手动） | 行当名**左侧**一枚 **6×6** 朱色小方印（`--gold` 实色，圆角 2px，内阴影 1px） | ⛔ **无** |
| ② **小叉**（可操作线索，仅手动） | 行右侧 **20×20** 圆形「回到自动」小叉可见 | ⛔ **无** |
| ③ **徽标**（文字线索，仅自动侧） | ⛔ **无字** | 行当名**右侧**一枚「**家里顶的**」徽标：4 字 / **≤11px** / 字色 `--wood-2` / 底 `color-mix(in srgb, var(--gold) 10%, var(--card))` / 圆角 4px / padding `1px 5px`（实测 **7.13 : 1** ✅） |
| ④ **字色**（明度线索，两侧都有） | 行当名 `--text` `#2e2318`（15.1:1） | 行当名 `--wood-2` `#6b4a2c`（7.8:1） |
| ⑤ **半透明**（仅顶着态） | — | `.is-fill` 头像 `opacity:.55`（自动态不降透明度） |

**互斥的三道保险**（架构师照此实现）：
1. **渲染层**：`.cast-seal` + `.cast-unset` 只在 `.is-picked` 分支拼进 HTML；`.cast-auto-tag` 只在 `.is-auto` / `.is-fill` 分支拼进 HTML；
2. **CSS 兜底**（防状态错乱时两种线索同框）：
   ```css
   .cast-row.is-picked .cast-auto-tag { display: none; }
   .cast-row.is-auto .cast-seal,
   .cast-row.is-fill  .cast-seal,
   .cast-row.is-auto .cast-unset,
   .cast-row.is-fill  .cast-unset,
   .cast-row.is-empty .cast-seal,
   .cast-row.is-empty .cast-unset,
   .cast-row.is-empty .cast-auto-tag { display: none; }
   ```
3. **切换动效**：手动 → 自动时，朱印 + 小叉**先淡出（200ms）**再由徽标淡入（⛔ 不交叉重叠，重叠瞬间会同时看见两条线索，玩家会以为"既手动又自动"）。

> ⛔ **界面上不出现"手动 / 自动 / 已指定 / 默认"这类词**（古风调性里很难看）。唯一的字是徽标那 4 个「家里顶的」，它本身就是世界观内说法（"家里自己顶上的人"），不穿帮。
> 无障碍：行容器 `aria-label` 给「这一位是你点的 / 这一位是按交情配的 / 这一位暂时由家里的顶着」，**只读屏可见，界面不显示**；徽标给 `aria-hidden="true"`（读屏已由行级 label 覆盖，避免读两遍）。

## 3. 三个动作（一键分派 / 按交情重新点一遍 / 每行小叉）

### 3.1 一键分派

| 项 | 规范 |
|---|---|
| 按钮 | 页面底部（`.cast-auto`，**主按钮**），文案「**按在册顺序 · 把没点的都点上**」 |
| 行为 | 遍历**未手动指定**的行当（自动态 / 顶着态都算没点），按 `spiritItems()` 顺序取**还没被占用**的沁灵依次填；一轮不够 ⇒ **循环复用**并给该行 `.is-conflict` |
| 结果 | 被填上的行**变成手动态**（`.is-picked`，带朱印 + 小叉） |
| 反馈 ① | 行逐个浮现：80ms 阶梯、每行 160ms、`--ease-out` |
| 反馈 ② | `toast(...)`（`app.js:384`）：「七位都点上了 · 往后这门人的戏就照这个扮。」（一键分派会填满所有未手动行 ⇒ ⛔ 不出「还差 N 位」这类算术提示，也不出现"差/缺/不足"） |
| 反馈 ③ | 7 位全手动 ⇒ 按钮变禁用（`.is-disabled`，`--gray`），文案改「都点齐了」 |
| ⚠️ | **不覆盖**已手动指定的行（手动优先） |

### 3.2 「按交情重新点一遍」—— **全局**按钮

| 项 | 规范 |
|---|---|
| 语义 | **撤销全部手动指定**，7 个行当**全部回到"按亲密度自动抽"** |
| 位置 | 一键分派**右侧**，两个按钮并排（`.cast-auto` 主 / `.cast-revert` 次） |
| 文案 | 「**按交情重新点一遍**」 |
| 视觉 | 次按钮：`--card` 底 + `--line` 描边 + `--wood-2` 字，⛔ 不用 `--gold` 实心（避免两个主按钮抢眼） |
| 确认 | **要二次确认**（这是撤销，不是填空）。用页面内确认条（⛔ 不用浏览器 `confirm`）：「都撤了？撤了之后，七位都回到按交情抽。—— 撤 / 再想想」 |
| 反馈 | 7 行同时切换（**串行**：朱印 + 小叉淡出 200ms → 徽标淡入 200ms，⛔ 不交叉，见 §4.5）＋ `toast`「都回到按交情了 · 七位重新抽过。」 |
| 禁用 | 一个手动都没有时 ⇒ `.is-disabled`（无可撤） |

### 3.3 「回到自动」—— **每行**小叉

| 项 | 规范 |
|---|---|
| 位置 | 触发器**右侧**，20×20 圆形按钮（`.cast-unset`），**仅 `.is-picked` 行显示** |
| 图形 | 一个细「✕」（1.5px 描边，`--wood-2`），⛔ 不用垃圾桶/叉号图标那种粗黑样式 |
| 语义 | 只撤**这一行**的手动指定 ⇒ 该行回到自动态 |
| 视觉 | 常态 `--line` 细描边；`:active` `scale(.94)`；⛔ 无底色（不抢触发器） |
| 反馈 | 该行切换（**串行**：朱印 + 小叉淡出 200ms → 徽标「家里顶的」淡入 200ms）＋ `toast`「「最老的那只」回到按交情了。」 |
| 无障碍 | `aria-label="回到按交情"`，⛔ 界面上不写字 |

### 3.4 不足 7 只时的**整体空态**（⛔ 不能看起来像出错）

玩家新号可能只有 1~2 只沁灵，7 行里大部分是"轮转复用顶上"的。这一屏必须**像在讲故事，不像报错**。

| 项 | 规范 |
|---|---|
| 位置 | `.cast-head` 下方、`.cast-card` 上方的一张 `.cast-all-note`（**仅当在册沁灵 < 7** 时出现） |
| 视觉 | `--card` 底 + 左侧 3px `--gold` 竖条，圆角 `--r-md`，14px / 行高 1.6 / `--text` |
| **定稿文案（⛔ 一字不改）** | 「**人少也不妨：性子像的先顶上，再一位扮上几位，家里轮着来。**」（28 字） |
| ⛔ | 不出现"不足 / 缺少 / 只有 / 还差 / 不够 / 错误 / 无法 / 至少"这类词；不用 `--red`；不用 ⚠ 图标 |
| 图标 | 可用一个小小的 🎭 或 🪢（与入口卡一致），⛔ 不用 ❌ / ⚠️ |

**为什么这句不能拆**：它的三个分句**正好对应代码的真实顺序** —— `castNearest`（性子像的先顶上）→ 一人扮多位（再一位扮上几位）→ `fill` 轮转复用（家里轮着来）。⛔ 架构师落地时**按原句序整句渲染**，不要因为排版拆成两句、也不要调换分句顺序。

**人数要不要显示 —— 要，但单列一行中性数据**（⛔ 不揉进上面那句）：

```html
<div class="cast-all-note">人少也不妨：性子像的先顶上，再一位扮上几位，家里轮着来。</div>
<div class="cast-count-line">台上七位 · 在册三位</div>
```

| 项 | 规范 |
|---|---|
| 文案 | 「**台上七位 · 在册 {N} 位**」（`·` 并列陈述，**两个数字平级**，⛔ 不作比较） |
| 视觉 | 12.5px / `--wood-2` / 无底色无描边 / 紧贴在 `.cast-all-note` 下方 6px / 左对齐与说明同缩进 |
| 判定 | `N = spiritItems().length`；**N ≥ 7 时整条不渲染**（`.cast-all-note` 也不渲染） |
| ⛔ | 不写「只有 N 位」「还差 M 位」「至少需要 7 位」——数字只陈述，不评价；`台上` 恒为 7（行当固定），不变动 |

> 这屏的整体语气：**"戏班人还没齐，先这么演着"**，不是"配置不完整"。

|---|---|---|---|
| 面板展开 | 220ms（`translateY(12px)→0` + 淡入） | `--ease-out` | 点触发器 |

### 7.2 本需求的实质（一句话给架构师）
**不是从零造选角，而是把"系统按亲密度自动抽"改成"玩家手动指定；没手动指定的行当仍走自动"。** ⇒ 每行有三种身份：**手动 / 自动 / 暂由人顶着**，由数据侧给标记（§6.3 #7），UI 只消费。

### 7.3 我做的判断（可直接落地，有异议请驳回）
1. 独立页 `#/maincast` + `#/main` 顶部入口卡（不做弹层、不做页内区块）；入口卡在 `.chap-prog` 之后、`.chap-list` 之前；未点过人时变醒目 + 角标，**不强制**引导。
2. 下拉 **自绘面板**（原生 `<option>` 放不进缩略图），另留视觉隐藏的原生 select 兜无障碍。
3. 选项 = 缩略图 + 名字 + 阶位；已指派时缩略图就在触发器里（不再另外放一个）。
4. 一键分派**不覆盖已手动指定**的行；不够时循环复用并标冲突。
5. `.is-fill`（轮转顶上）**绝不能显示成"已指派"** —— 半透明 + 徽标 + 定稿 14 字「还没点，这位是家里自己顶的。」（⛔ 不写"暂且没人"，头像 + 名字明明在，说"没人"自相矛盾）。
6. 手动 vs 自动用**互斥双线索**：手动 = **朱印 + 小叉（无字）**，自动 / 顶着 = **「家里顶的」徽标（≤11px）**；⛔ 双线索绝不同框（渲染层 + CSS 兜底 + 动效串行三道保险）。字色仍作副线索（`--text` vs `--wood-2`），不靠单一颜色 ⇒ 色弱可辨。
6b. 徽标 11px 是**上限不是推荐值**：实测 `--wood-2` 在 `gold 10% + card` 底上 **7.13:1** ✅（远超 4.5:1），所以 11px 可安全使用；⛔ 不再往上加，也不配更浅的字色。
7. 全局撤销**要二次确认**（页面内确认条，⛔ 不用浏览器 `confirm`）。
8. 全走 CSS 变量 + 新增 5 个尺寸 token；**不进沉浸模式**，沿用现有手账皮肤。
9. 说明小字用 `--wood-2`（实测 7.8:1）；⛔ `--text-2`（4.28:1）与 `--gold`（2.98:1）不作正文。
