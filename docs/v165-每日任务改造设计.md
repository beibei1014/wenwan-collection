## 二、设计目标与闭环

### 2.1 一句话目标
**把每日任务改造成「菩提根日常」——每天 5 件与菩提根有关的小事，做完给礼物，礼物拿去递给你在意的沁灵。**

### 2.2 闭环（⛔ 不重复计数）
```
  每日任务（菩提根相关）
        │ 完成
        ▼
  发「礼物」到 ww_gifts          ← 任务只动库存，⛔ 不碰亲密度
        │ 玩家主动「递一件」
        ▼
  giveGift()  → rec.bond += 4/6  ← 亲密度只在这里涨（唯一入口）
        │
        ▼
  羁绊八档 ↑ → 称呼改口 / 恋爱线门槛 / 岁除滋养贡献
```

> 🔴 **不重复计数铁律**：**任务奖励只发礼物（`addGift`），绝不直接加 `rec.bond`**。亲密度**只能**经 `giveGift()` 涨（§三.4）。所以「做任务」与「涨亲密度」之间**隔着一次玩家主动的『递一件』**——这正是用户要的「主动经营」（v164l §二）。

### 2.3 「为现在的系统服务」——任务只喂既有行为
⛔ 不引入与主线无关的杂项。任务条件**只能**取自**已有的**玩家行为：

| 行动键 | 取自现有行为 | 证据 |
|---|---|---|
| `greet` | 打开沁灵详情看今日问候 | `greetingOf/ensureGreet` `spirits.js:6761` |
| `play` | 今日盘过一只菩提根 | `item.lastPlayedAt`（`spirits.js:4626`） |
| `care` | 照料三式（擦净/静坐/理线） | `CARE_CFG` `spirits.js:2828`（UI 待接，见 §七-4） |
| `gift` | 递一件给它 | `giveGift` `spirits.js:2955` |
| `night` | 参加一次夜话 | `NIGHT_EVENTS` `spirits.js:6778` |
| `read` | 读一章「串与我」 | `readChapter` `spirits.js:6772` |
| `board` | 看一次岁除榜 / 结局旗 | `evaluateEnding/endingFlagsOf` `spirits.js:6784` |
| `look` | 打开详情看「纹 / 修行进度」（**需新埋点**，见 §七-9） | `stageProgress` / 详情页 |
| `reply` | 回一封信 | `replyDiary` `spirits.js:6763` |
| `town` | 看一次沁灵巷 | `townEvents` `spirits.js:6768` |

> **关于「盘」的口径**：文中的「盘玩 / 盘一串」**指手串本体的既有机制**（`item.playStatus` / `item.lastPlayedAt` / `item.playCount`，`spirits.js:4626`），是**针对物件的操作**；⛔ **不是**对沁灵的物件化动作。沁灵是**人**，用 `{ta}`——对沁灵一律用「陪伴 / 照料 / 递一件」，⛔ 不用「盘」。此口径同时约束任务文案。

## 三、新方案

### 3.1 数量与结构
- **每日固定展示 5 个**（满足用户要求 · 大纲 §13.1-1「⛔ 不多不少」）。
- **按大纲 §13 定稿的 5 个固定任务**（净手/陪坐/看纹/守灯/应声，§3.2）。
  - ⛔ 备选（日后）：若嫌固定不耐玩，可扩成 **7 挑 5**（当天固定、跨设备一致，沿用 `mulberry32` 种子法 `game.js:196-213`）。→ 见 §八-待定。
- **每任务奖励 = 1 件礼物**（详见 §3.3）。
- 完成态**持久化**（现状不持久化，是靠时间戳现算）——新增 `ww_daily` 台账（§五）。

### 3.2 五个任务 · **正式案**（★ v165e：已由大纲 §13 定稿，本设计采纳为主方案）

> 出自 `v165-故事大纲.md` §13.2，由编剧（文成章）定稿。⛔ 全围绕菩提根，0 处其他文玩类别。
> ⛔ 说明文案**无机制词**（不出现「任务 / 奖励 / 好感度 / 完成 / 领取」），写成**这一家人自己会说的话**（大纲 §13.1-4）。

| # | 任务名 | 一句话说明（这家人自己会说的话） | 行动键（本设计定） | 产出礼物 | 礼物类 |
|---|---|---|---|---|---|

| 2 | **陪坐** | 「坐下，什么都不用说。」 | `care`（照料） | 一盏热茶 / 一碟点心 | 人情 |

- **行动键映射（本设计定 · 可调）**：5 个任务分别喂 `greet / care / look / night / reply` 五个既有行为（§2.3 表）。⛔ 若某键尚未有可检测信号（如 `care` 照料三式未接 UI、`look` 看纹需新埋点），由架构师按 §七-9 决定：**先以最近的既有信号顶替**（如 `care`→`play`、`look`→`greet`），**不改任务名**。
- **礼物对应偏好**（大纲 §13.2 已核）：器物→`dignified`/`cool`；织物→`scholar`/`gentle`/`sweet`；声响→`lively`；奇异→`mystery`；人情→通用。⛔ **坚韧类不出现在每日任务**（这一门没有「野」型）。
- **每任务产出 2 候选礼物中的 1 件**（如「净手」给茶则或素砚其一），由**日期种子**决定当日发哪件（当天固定、跨设备一致）。

#### 3.2.1 备选参考（已被 §13 定稿取代，保留备查）
早前设计的两套候选曾为：**方案 A「一日的功课」**（晨起一照/盘一串/静坐一炷/递一件/夜话一场）与 **方案 B「一门的人」**（认一认家/说一句/走一趟巷/递一件给它/读一章）。⛔ 现以 §13 正式案为准；如日后需增补第 6–7 条进池，可从此处取。

### 3.3 奖励与既有 `GIFT_CFG` / `GIFT_CATALOG` 的关系

| 问题 | 裁定 |
|---|---|
| 奖励发什么？ | **发 `GIFT_CATALOG` 里的具体 `giftKey`**（一件），经 `addGift(ww_gifts, key, 1)` 入库存 |
| 与 `GIFT_CFG` 的关系？ | 任务奖励**不读也不改** `GIFT_CFG`（那管「送出」的羁绊值与日上限）。它是**入账**（库存 +1），`GIFT_CFG` 管**出账**（库存 −1、bond +4/6）——**两条路分离** |
| 会重复计数吗？ | ⛔ 不会。任务只 `+1 库存`；亲密度只在 `giveGift` 里涨。**任务→礼物→送礼→亲密度，是两跳** |
| 奖励能否是 XP？ | 建议**礼物为主，保留少量 XP 作辅**（否则既有等级/成就系统会断粮，`computeXp` `game.js:84-147`）。→ 见 §八-待定 |

### 3.4 与「8 来源」的关系（⛔ 不打架）
第一批送礼设计的**礼物来源之一**本就有「每日一签 / 成就」等（见 `v165-亲密度与送礼系统设计.md` §3.1）。本次的**每日任务**是**新增的第 9 条来源**，且是**主力来源**（每天稳定 5 件机会）。⛔ 需在发放账本里去重，避免与「每日一签」重复发同一件。

### 3.6 对大纲 §13.4 五个机制问题的裁定（本设计域）
| # | 问题 | 裁定 | 依据 |
|---|---|---|---|
| 1 | 任务是否分「进阶级」（按修行阶段解锁不同任务） | **先不分级**，5 个全天候可做；分级留后续 | 与「零操作玩家不被落下」一致；⛔ 分级会落下轻玩家 |
| 2 | 每日礼物发放上限 | **≤5 件/日**（做完 5 个各 1 件）；与送礼「全局 ≤2 件/日」**分开计**（任务所得**不受**送礼上限约束） | 合并会压抑做任务的乐趣 |
| 3 | 同一任务可否重复做 | **每任务每日 1 次**，⛔ 不可刷 | 防挂机式刷礼物 |
| 4 | 是否设「失败」 | **不设失败**；没做就是没做，次日再来，⛔ 不惩罚 | 与「系统绝不主动伤害玩家」一致 |
| 5 | 任务提示语气 | **保留**「这家人自己会说的话」现语气（⛔ 不出现机制词）；若嫌长可压到 4 字（如「净手」下只留「先洗手」） | 大纲 §13.1-4/5 |

> **闭环铁律复述**：5 个任务**只发礼物**（`addGift`），⛔ **都不直接调 `addBond`/`giveGift`**；亲密度只在玩家「递一件」时经 `giveGift` 涨（§2.2）。

## 四、防刷 / 离线 / 跨设备

| 项 | 规则 | 说明 |
|---|---|---|
| **每日重置** | 按**本地日** `dayKey`；`ww_daily.day !== today` → 清空 `acts` 与 `claimed`（**保留**累计/连续记录） | 与 `rooms.js:31 todayKey()` 同口径 |
| **补做？** | ⛔ **不补做**。漏一天就漏一天 | 但**奖励很小（1 件礼物）且礼物另有他源** → 「漏一天不惨重」，符合「不逼玩家天天上线」精神 |
| **防刷** | 每个行动键**当日只记 1 次**（`markDaily` 去重）；每个任务**只能领一次**（`claimed[taskId]`） | ⛔ 不可重复领 |
| **发礼物去重** | 领奖时写 `claimed`；与 `ww_story.giftSeeded`（第一批来源账本）比对，⛔ 同键当日不重发 | 防「任务 + 签到」双发 |
| **离线** | `ww_daily` 本地优先（同 `ww_gifts` `spirits.js:2942` 风格） | 断网照常做任务 |
| **跨设备** | **建议把 `daily` 并入既有 `gift_store.data`**（`db.js:463-499`），**⛔ 不另起新表、不另起同义字段** | 见 §五.2 |
| **冲突合并** | `daily` 合并规则：**取 `day` 较新的整份**；同 `day` 则 `acts` 逐键取 `max`、`claimed` 逐键取 `or` | 与 `mergeGiftStores` 的「gifts 取 max」同精神，需架构师扩展该函数 |
| **⛔ 不进 marks** | 台账**零写 `rec.marks`**（字典序裁剪 bug，`spirits.js:342-344`） | 承重红线 |
