## 〇、AVG 演出规格（⛔ 当前代码全缺，这一节就是需求书）

我核实过：`backgroundImage` / `sceneBg` / `backdrop` / `standPos` **全项目 0 命中**，`renderTalkPage` 只渲染 `.nt-chat-head` + 气泡流。
**所以下面四层里有三层要新建：**

| 层 | 现状 | 需要什么 |
|---|---|---|
| **① 背景** | ⛔ **无** | 一个全屏底图层，随镜号切换 |
| **② 立绘 / 站位** | ⛔ **无** | 立绘层 + 左右站位；**说话者移到中/前，未说话者退后排**（AVG 常规做法） |
| **③ 对话框** | 🟡 **有**（气泡流） | 改成 **底部一条：角色名 + 台词** |
| **④ 旁白** | 🟡 有（`w:"sys"`） | ⛔ **收紧到 ≤3 行，且每行必须挂在一次画面变化上** |

**行数据格式（建议）**：
```js
{ w:"sys", bg:"BG-01", t:"…" }              // 旁白：切背景
{ w:"sp",  bg:"BG-02", at:"R", who:"记账的那只", ps:["scholar"], t:"…" }  // 说话：切立绘站位
{ w:"me",  t:"…" }                          // 玩家台词
{ bg:"BG-02", ch:["我替{ta}上。", "…"], lv:["借势","同尘"] }   // 选项：过滤后全空则退回全部
```

## 六、🔴 密集恐惧症（trypophobia）硬约束 —— **本项目所有美术产出的第一约束**

> 用户原话：「**我有密集恐惧症。**」
> **这是身体反应，不是审美偏好。任何密集排布的图案都不能出现在画面里。**

### 6.1 ⚠️ 最危险的就是「菩提串」本身

一串菩提天然是**几十颗大小相近的圆珠紧密排列**——**这恰好是密集恐惧症的典型触发图**。
⛔ **所以本项目的立绘 / CG 一律不许出现「一串密珠」。**
✅ **龙脊菩提是天然安全的**：高桩、疏朗、轮廓分明。**它反而是最好的示范样板。**

### 6.2 反密集约束句（英文原文，**追加到 prompt 末尾**）

⛔ **位置极重要：必须是 prompt 的最后一段。**（同文件里 `PROPORTION LOCK` 的注释写着「模型对末尾最敏感」，这条同理。）

```
DENSITY LOCK — highest priority, overrides every other style note. Absolutely avoid: strings, rows, clusters or piles of small round beads; spheres, pearls, pebbles or seeds grouped together; any grid, lattice, checkerboard or honeycomb repetition; dot matrices, stippling, halftone, dense micro-patterns, speckled texture; scattered small round objects filling the frame. If a round bead, pearl, bead bracelet or necklace must appear at all, show a maximum of 3 pieces, spaced far apart with wide clear empty space between them, each one individually readable as a separate shape, never touching or overlapping. Keep the whole composition sparse, airy and uncluttered, with large calm areas of plain background, flat simple shapes and clean negative space.
```

**为什么这样写才有效**（⛔ 不是「no dots」那种无效词）：
| 要求 | 覆盖到的 |
|---|---|
| 密排圆珠 / 密排小球 / 重复图案 | `strings, rows, clusters or piles of small round beads` + `grouped together` + `dense micro-patterns` |
| 点阵 / 网点 / 密集纹理 / 颗粒堆叠 | `dot matrices, stippling, halftone, speckled texture` + `piled granules` + `scattered small round objects filling the frame` |
| 规则重复排列 | `any grid, lattice, checkerboard or honeycomb repetition` + `rows` |
| **正面替代物** | `a maximum of 3 pieces, spaced far apart, wide clear empty space, individually readable, never touching or overlapping` |
| 整体疏朗 | `sparse, airy and uncluttered, large calm areas of plain background, clean negative space` |

### 6.3 插入位置（四条路径，统一挂 `CG_STYLE` 末尾）

| 路径 | 装配点 | 怎么插 |
|---|---|---|
| **① 立绘** | `appearancePrompt(ap)`（`spirits.js:1746-1760` 的 `hard` 数组）＋ `buildLookTags`（`:2492`） | 推入 `hard` 数组末尾（与 `noFeat` 那些同级） |
| **② 突破 / 故事 CG** | `storyCgPrompt`（`:3239`） | 拼在 `CG_STYLE + …` 之后，作为**最后一段** |
| **③ 节令 CG** | `promptForCg`（`:6135`） | 同上 |
| **④ 全家福 / 自定义 CG** | `:6154` 的 `CG_STYLE + ", " + mood + ", "`、全家福线程（`:4352` `tag:"全家福"`） | 同上 |

> 💡 **最小改动方案（我建议）**：四条路径最终都拼到 `CG_STYLE`，而 `CG_STYLE`（`spirits.js:6110-6116`）已经以
> `… + ANATOMY + ", " + NEG_STYLE` 收尾。

### 6.6 ⛔ 我自己埋的雷：「十七级台阶」（**已改**）

**自审结论：有。我用「一串密珠」讲故事了吗？没有；但我用了同类的东西——「台阶十七级」。**

记账的那只数台阶，数了很多年。这是它的性格（记性好、做了很久），但 ⛔ **十七级台阶在画面上就是十七条等距横线 = 规则重复排列**，和密集恐惧症同源。**而且我在 v164k 和 v164m 两版里都用了这个意象。**

**已改。** 现在它数的不是级数，是**被踩得发亮的那几级**：

| 原 | 现 |
|---|---|
| 「十七级。我又数了一遍。」 | 「**被踩亮的那几级**，我又数了一遍。」 |
| 「我也数了！十七减一，十六！」 | 「**我也数了！四级！你上次说五级！**」 |
| 「……你往回减。」 | 「**……我数的是亮的。**」 |
| 镜 2 画面：台阶一格一格亮到顶——十七格 | 镜 2 画面：⛔ **台阶大半在阴影里，只有三四级被踩得发亮** |
| BG-01 规格：十七级石阶 | ⛔ **不要数得清级数** |

**为什么这样改更好（不只是为了雷）**：
> 原来「十七级」是一个**数字**，讲的是「它记性好」。
> 现在「被踩亮的那几级」是一个**画面**，讲的是「**它记得被走过的路**」——**它数的是你回家踩过的那几级。**
> ⛔ 而且它在画面上天然只有三四级亮点，**反密集这条顺手就满足了**。

**⚠️ 同一类雷，全项目都要查一遍**：
| 意象 | 为什么危险 | 建议 |
|---|---|---|
| **一串珠** | 密排圆珠 | ⛔ 删 |
| **数台阶 / 数瓦** | 规则重复 | ✅ 改成「数被踩亮的」 |
| **满地散珠** | 颗粒堆叠 | ⛔ 删 |
| **成群站位**（全家福） | 等距排列 | ✅ 错落站位，前后三档纵深 |
| **账本格子 / 名录格子** | 网格 | ⛔ 别画成格阵 |
| **灯笼串 / 珠帘** | 重复垂坠 | ⛔ 最多 3 盏，间距拉开 |

⛔ **以上六条建议进 `avg-game-kit` 的美术铁律**，因为它们不是文案的偏好，是**生理不适**。
