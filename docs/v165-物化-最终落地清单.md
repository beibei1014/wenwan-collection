## 四、渲染层规则：第一人称「我」的显示（供架构师落地 · **只写规则，不写实现**）

> 背景（team-lead 裁定①）：沁灵的独白 / 台词大量用**第一人称「我」**——这是**人**的正常口吻，⛔ **不许逐行改成人名/第三人称**（会把口吻改坏）。正确做法：**在渲染层统一给「指称」**。以下为规则与边界条件。

### 4.1 先按「有没有说话人名牌」分三类

| 类型 | 典型展示位 | 名牌来源 | 规则 |
|---|---|---|---|
| **A · 对话流（有名牌）** | 群聊 / 夜话剧场（`NIGHT_EVENTS` 的 thread 对话）、主线 9 章对话框泡泡 | 每条消息带 `w` / `who` 字段 → 界面显示说话人名/头像 | **「我」原样保留**，⛔ 不替换成人名 —— 名牌已告诉玩家是谁 |
| **B · 独白式文本（无名牌）** | 回响信 `ECHO_LETTER`、节令台词 `FEST_LINES`、日记 `DIARY`、来信 `localLetter` / `letter` | 无（整段粘贴） | **「我」原样保留**；但**必须在该展示位外层补说话人指称**（见 4.2） |
| **C · 系统旁白** | `w:"sys"` 行、系统 toast、里程碑、任务描述 | 无（非沁灵口吻） | 旁白**不得用「我」指沁灵**；用 `{ta}` / 他 / 她 / 名字 / 那只，或**去主语** |

### 4.2 无名牌位（B 类）怎么补指称 —— 只许「加法」

- **优先用已有的、无侵入的位置补**，⛔ 不改正文「我」：
  - **回响信**：落款本已签名（`—— 你的{name}`）；⚠️ 若某封**缺落款** → **补落款**，⛔ 不动正文。
  - **节令台词**：界面标题/气泡已带形态名或图标；若仍歧义 → 在**题头**加「{name}说」这类**外层标签**，⛔ 不动台词。
  - **日记**：题头「第 N 天 · 形态名」→ 若需，题头**补 `{name}`**。
- **⛔ 禁止**：把正文「我」逐句替换成第三人称/人名；⛔ 禁止在正文里插说话人名字（会破坏口吻）。

### 4.3 「我」与「{name}」混在同一句

- 同句/同段**同时**出现「我」和「{name}」（如「我叫{name}。是从那串里醒来的。」）：**两者都保留** —— 「我」是自称、「{name}」是自我介绍，语义不同，⛔ 不合并、不互换。
- 「{name}」为**运行时占位符**（说话人＝这只沁灵自己）：**保留占位符**，渲染时按当前沁灵名替换；「我」不动。
- 一句里出现**两个不同沁灵**的第一人称（转述，如 A 说「{B}跟我说『我害怕』」）：内层引号里的「我」＝B，**保留**；外层按 A 的视角。⛔ 不做人称改写。

### 4.4 系统（旁白）vs 角色（沁灵）—— 必须区分

- **系统位**：`w:"sys"` / 系统 toast / 里程碑 / 任务描述 → ⛔ 不用「我」指沁灵、⛔ 不用「它」指沁灵（用 `{ta}`/他/她/名字/那只）。
- **角色位**：`w:"A/B/C/sp/me"` / 台词 / 独白 → **允许且应当用「我」**（人话）；「它」只允许出现在**反派刻意物化**的台词，或**指实物串/道具**时。

### 4.5 边界条件（给架构师的断言）

- 本规则**只做「补名牌 / 补落款 / 外层标签」这类加法**，⛔ 不做人称改写、⛔ 不改正文用词。
- **占位符名与数量不变**，池子长度不变 ⇒ **无需改长度断言**。
- 名牌归属由既有 `w` / `who` 字段决定，⛔ **不新造来源**；无法判定说话人的文本（B 类）走 4.2 的「补指称」而非改文。
- 适用范围：**所有**「角色第一人称台词 + 名牌来自 `w`/`who`」的展示位（群聊/夜话剧场、主线 9 章对话框、回响信、节令台词、日记、来信）。
