## 0. 一句话结论 & 六条硬约束

**结论**：事件卡做**三级**（日常 / 要事 / 节点）+ **单张队列**（⛔ 绝不叠卡）；纪事页 `#/events` 做**按日分组 + 五类筛选 + 30 条分页**；画册 `#/album` 做**四册 tab + 3/4 列宫格 + 「正在展示」标记**；导航把「沁灵巷 `#/town`」升成二级 hub，**沁灵页只留两张入口卡**，房间/纪事/画册全部收进 hub（hub 卡上的 chip 保留一层直达，⛔ 不多点一次）。

## 1. 事件卡片（三级 + 单张队列）

### 1.1 级别的定义与判定权

**判定权在数据层，UI 只消费。** 架构师在 `recordEvent(rec, ev)` 里加一个 `level` 参数，UI 读 `ev.level`，⛔ UI 里不写 `if (type === "fest")` 这类判断（否则以后加事件类型要改 UI，违反「剧本与代码解耦」）。

| 级别 | 类名 | 语义 | 停留 | 按钮 | 出现频率预期 |
|---|---|---|---|---|---|
| **l1 · 日常** | `.evt-card.is-l1` | 一件小事：递了东西、今日任务做完、写了日记 | **2600ms** 自动收 | ⛔ 无 | 高（一天几次） |
| **l2 · 要事** | `.evt-card.is-l2` | 值得停一下：亲密度进阶、读完一章、夜里聊出个结果 | **6000ms** 自动收 | ✅「去看看 ›」 | 中（几天一次） |
| **l3 · 节点** | `.evt-card.is-l3` | 一年就几次：**岁除**、蜕形 / 化形、小岁除、天劫、结局节点 | **不自动收**，必须点「记下了」 | ✅「记下了」 | 低（一季一两次） |

**建议的默认映射表**（写在 `spirits.js` 的集中配置里，UI 不硬编码；架构师可按实际调整）：

```js
// v174：事件级别（集中配置 · 单一数据源）—— 缺省回落 l1
const EVENT_LEVEL = {
  milestone: "l3",   // 挂瓷开沁 / 纪念日
  fest:      "l3",   // 节令 · 岁除（一年四次的那种）
  chapter:   "l2",   // 读完一章
  night:     "l2",   // 夜话一幕有了结果
  bond:      "l2",   // 亲密度进阶（新增 type）
  gift:      "l1",   // 递了一件东西
  quest:     "l1",   // 今日任务做完
  diary:     "l1",   // 写了日记
};
```

> ⚠️ **⛔ 不要用「恶人来袭」这种外号当 type**。type 是代码键，用英文小写词（`raid` / `omen` 之类由架构师定），**玩家看到的中文标题由剧本/文案给**（走 `ev.title`）。本文只规定「级别怎么画」，不规定「有哪些 type」。

### 1.5 队列策略（**本批最关键的一条**）

**问题**：现在 `flushEventPops()` 把 drain 到的**全部** pops 一次性 append（`app.js:3707-3721`），几条就同位置叠几张 —— 用户看到的是糊成一坨。而且 `router()` 每次切页都调一次（`app.js:10170`），局部重渲染也调一次（`app.js:4332`）⇒ 一次操作后切个页，同一批事件可能又被 drain 一次（`_eventPops` 已清空所以不会重复，但**同一 tick 的多条一定叠**）。

**规范**：拆两步 + 一个队列。

```
recordEvent ──push──▶ _eventPops（现有）
                          │
router/局部重渲染 ─ flushEventPops() ─ drain ─▶ _evtQueue（新 · 待播队列）
                                                     │
                                          pumpEventQueue() ──▶ 同一时刻只挂 1 张 DOM
                                                     │
                                    收掉（自动/点击）──▶ 播下一张
```

| 规则 | 值 |
|---|---|
| 同时在场卡片数 | **恒为 1**（⛔ 第二张必须等第一张收掉） |
| `_evtQueue` 上限 | **3**；超出部分**并入一张 l1 汇总卡**（见下），⛔ 不丢事件（`rec.events` 里都有，纪事页看得到） |
| 排序 | ① **l3 插队到队首**（节点事件优先）② 同级按 `at` 升序（先发生的先播） |
| 播放中又来新卡 | 进队列，⛔ 不打断当前这张 |
| 页面切换时 | 队列**继续播**（⛔ 不因为切页丢掉）；`flushEventPops` 只入队不出队 |
| l1 合并阈值 | 同一 tick drain 到 **≥3 条同级 l1** ⇒ 合并成一张汇总卡 |
| 汇总卡 | 标题「**今天又添了几件小事**」（≤16 ✅）；一句话「**还有 N 件 · 回头在纪事墙上看。**」；无按钮；停留 2600ms |

### 1.6 事件卡的四种状态

| 状态 | 触发 | 表现 |
|---|---|---|
| **有数据（常态）** | 队列非空 | §1.2 结构；进场 `evtIn`（复用 `skin.css:1233`），出队 `evtOut`（复用 `skin.css:1234`） |
| **加载中** | ⛔ **不适用** —— 事件卡是同步推入的（`recordEvent` 当场 push），**没有网络等待** | ⛔ 不给骨架屏、不给 loading（给了反而是假动作） |
| **空态** | 队列空 | ⛔ **什么都没有**（不是「暂无事件」的卡）。事件卡是主动推送，空就不出现 |
| **出错** | 数据结构异常（`ev` 缺 title / `rec.events` 非数组） | ① 该条**静默丢弃**（`try/catch`，⛔ 不弹错）；② 其它事件不受影响；③ ⛔ 不出现「加载失败」这类后台话 |

## 6. 动效表 + reduced-motion

| 动效 | 时长 | 缓动 | 触发 |
|---|---|---|---|
| 事件卡进场（l1/l2） | 260ms（`translateY(-10px)→0` + 淡入 + `scale .98→1`） | `--ease-spring`（复用 `evtIn`） | 出队 |
| 事件卡出场 | 240ms（淡出 + `translateY(-8px)`） | `--ease-out`（复用 `evtOut`） | 自动收 / 点击 |
| **l3 遮罩淡入** | 200ms | `--ease-out` | 出队 |
| **l3 卡片弹入** | 300ms（`scale .94→1` + 淡入） | `--ease-spring` | 同时 |
| **队列接棒** | 出场完 **200ms 停顿** 再进场下一张 | — | 上一张收掉 |
| 纪事行入场 | 160ms，阶梯 **30ms**（上限 10 行） | `--ease-out` | 进页 / 换筛选 |
| 换筛选重绘 | 120ms 淡出 → 160ms 淡入 | `--ease-out` | 点 chip |
| 画册格渐显 | 180ms | `--ease-out` | 图就绪 |
| 「再往上翻」追加 | 160ms，阶梯 30ms | `--ease-out` | 点按钮 |
| hub chip 按下 | 120ms `scale(.96)` | `--ease-spring` | `:active` |

> ⛔ **克制纪律**：本批只有「淡入 + 轻微位移 + 一个小 pop」。⛔ 不做视差、不做粒子、不做数字滚动（纪事是**回看**场景，晃会妨碍读）。
> ⛔ **不叠动效**：事件卡出场与下一张进场**串行**，⛔ 不交叉（同位置交叉会看成一张卡在闪）。

**减动态降级（项目已有 `prefers-reduced-motion` 约定，本页补齐）**：

```css
@media (prefers-reduced-motion: reduce) {
  .evt-card, .evt-card-mask, .evt-row, .evt-tab, .evt-day,
  .album-cell, .album-more, .hub-card, .hub-chip, .evt-more { transition: none !important; animation: none !important; }
  /* l1/l2 停留时长⛔ 不缩短（缩短会让"没看清就没了"），只去掉动画 */
}
```
