## 0. 格式契约

沿用现有 `CHAP_SCRIPTS` 结构，**只新增三个可选字段，零破坏**。（定位按常量名，不按行号——`spirits.js` 正在被并发改动，行号会漂移）

```js
{
  cg: "CG-04",                     // 【新增·章级】本章章末弹哪张 CG；不写 = 本章无 CG
  start: {
    lines: [
      { w: "sys", t: "夜里，你把它从桌上拿起来。" },      // w: "sys" 旁白 / "sp" 沁灵说话
      { w: "sp",  t: "{call}。" },
    ],
    next: "c1",                    // 唯一出口
  },
  c1: {
    lines: [ { w: "sp", t: "……" } ],                      // 停在「等你选」
    choices: [
      { t: "我妈也不知道。", go: "m1", tone: "quiet", mark: "c2_forgot" },  // 值 = 全局唯一完整 key（cN_token）
    ],
  },
  m1: { lines: [...], next: "c2" },                        // 分支中段
  e_warm:  { lines: [...], ending: { key: "warm",  name: "🌙 标题", text: "结局文本" } },
  e_quiet: { lines: [...], ending: { key: "quiet", name: "🌙 标题", text: "结局文本" } },
}
// ending.key ∈ { warm, cool, quiet }：走哪个结局由 `go` 决定；key 只作存档 / 后日谈 / 相册标签，不参与路由
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `w` | `"sys"` / `"sp"` | 旁白 ／ 沁灵。**没有 `"me"`** —— 玩家的话由 `choices` 的 `t` 承担，选中后引擎自动插一条 `mine` |
| `tone` | `"quiet"` / `"warm"` | 主线只有这两种（已核实：现有 8 章 40 个选项只有 quiet(17) / warm(23)）。**不要用夜话的 cool/fun** |
| `mark` | 8 处节点 / 19 个值 key | 见 §5。**值 = 全局唯一完整 key**（如 `c4_greedy`），引擎写 `rec.marks[值] = 1`。缺失 = 不记账，向后兼容 |
| `cg` | `"CG-01"`~`"CG-08"` | 章级，写一次。引擎在 `t.ended` 时弹确认 |

**规模纪律**：`CHAP_TALK_CAP = 40` 是保险阀，它按**单条路径累计条数**判——`chapWalk` 在选项节点上发现 `t.msgs ≥ 40` 就**自动跳到 `choices[0].go`**（跳过对白并替你选第一项）。本稿**最长单路径 = 39 条（第 7 章）**，离保险阀只差 1 条，**任何"再加一句"的改动都不能落在第 7 章**。

**占位符一律用 ASCII key**（见 §7）：`{tixing}` 而不是 `{胎性}`。主线台词走 `fmt`（硬编码 replace 链），夜话/丝线走 `thText`（正则 `/\{(\w+)\}/g`，`\w` 不匹配中文）。ASCII key 让**两条路径同时安全**，不依赖那次正则修复是否上线。

## §3 胎性 · 木本纪（木为本源）

> 本项目专注文玩，且以**木与果核**为骨。故《沁灵纪》的胎性观以**木胎为「本源」**，余者为「旁支」——不是五类并列，而是「一源分四流」。

### 3.1 一源四流
| 胎性 | 定位 | 判定（依 `tiXingOf`，见互动系统 §A.6） |
|---|---|---|
| **木胎** | **本源**（原生 / 主流材质） | `species` 含 菩提/核/椰/木/果/核桃/橄榄/库克/紫金鼠/象牙果 |
| 石胎 | 旁支 | 含 晶/石/玉/翠/玛瑙/松/岫/青金/曜/玺/玉化 |
| 脂胎 | 旁支 | 含 蜜/蜡/珀/琥珀 |
| 金胎 | 旁支 | 含 金/银/铜/钛/钢/锡 |
| 杂胎 | 旁支（兜底） | 拼图/动漫周边/盲盒，及一切不中者 |

> 木胎为本源：沁灵化形，原是木珠、果核在掌中养出灵性——「开沁」最初只在木与果核上发生。石、脂、金之属亦有沁灵，但皆是从木本之气分流而出的「后起之秀」，故列旁支。

### 3.2 木属细分（本源之下再分）
木胎内部，以**菩提类**为正脉——它也是本项目**主串的标准来源**（你手里那串，十之八九解析为「木胎」）。
`categories.js`「菩提」分类现有 12 项，全部木 / 果核：

| # | 品种 | 备注 |
|---|---|---|
| 1 | 菩提根 | 本源之根 |
| 2 | 库克 | 木椰一类 |
| 3 | 金刚菩提 | 木果核 |
| 4 | 凤眼菩提 | 木果核 |
| 5 | 千眼菩提 | 木果核 |
| 6 | 菩提根·白玉 | 菩提根之变 |
| 7 | 紫金鼠 | 果核（鼠李） |
| 8 | 椰壳 | 椰木之壳 |
| 9 | 象牙果 | 果核（棕榈） |
| 10 | 核桃 | 木果核 |
| 11 | 橄榄核 | 木果核 |
| 12 | 菩提根·老料 | 菩提根之变 |

> 菩提类之外，木胎尚有硬木（黄花梨、紫檀）、软木（沉香、檀香）等，皆归本源，不立专表。
> 旁支胎性（石/脂/金/杂）亦可入主线、亦可成主串，但**默认主串以木胎（菩提类）为先**——`{tixing}` 在绝大多数玩家手里解析为「木胎」。

### 3.3 古风纪律
- 所有沁灵统一中国古风，禁现代 / 西式 / 日式措辞。「木本纪」「本源」「旁支」取自古史书体例（如《本纪》《本草》），与此一脉相承。
- 占位符仍一律 ASCII：`{tixing}` 而非 `{胎性}`（见 §7）。本表不引入任何中文占位符。

## §7 占位符：全部用 ASCII key（本稿既定，不是提案）

**本剧本全部用 `{tixing}` / `{keepsake}` / `{said1}` 这类 ASCII key，不用 `{胎性}` 这类中文 key。**

原因：主线与选项走 `fmt(tpl,v)`，夜话 / 丝线走 `thText(t,v)`（正则 `/\{(\w+)\}/g`）。
- `thText` 的 `\w` **不匹配中文** → 中文 key 在夜话侧会**静默不被替换**（已下单修，任务 D）；
- ASCII key 让**两条路径同时安全**，不依赖那次修复是否上线。

⚠️ **`fmt` 是硬编码 replace 链（现 9 个 key：`days` / `idle` / `plays` / `color` / `stage` / `bead` / `call` / `name` / `year`），不是正则。** 所以主线要用的 5 个新 key，必须**`greetVars` 造值 + `fmt` 加 replace，两处都改才生效**：

| 新 key | `greetVars(item,rec,ctx)` 里怎么造 | 备注 |
|---|---|---|
| `{tixing}` | `tiXingOf(item)` | 纯函数，由 `item.species` 推导（函数名听架构师的） |
| `{keepsake}` | 读全局 `ww_story.wuhe` | ⚠️ `greetVars` 的签名里没有全局——需在 `chapWalk` 里单独读一次再塞进 `v`，或给 `greetVars` 开一个口子 |
| `{said1}` `{said2}` `{said3}` | `SAID_LINES[rec.marks 章序最早三条]` | 兜底 `DEFAULT_SAID_POOL[hash(item.id) % 4]` |

> 定位一律**按函数名**（`fmt` / `greetVars` / `chapWalk`），**不按行号**——`spirits.js` 正被并发改动（本轮已 +235 行），本文件里出现的旧行号会漂移。
