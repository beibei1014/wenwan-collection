## 〇、三条不可动摇的设计公理（先立规矩）

| # | 公理 | 落到本系统 |
|---|---|---|
| 1 | **沁灵是人，是修行者**（`{ta}`） | ⛔ 0 处物件化动作（手心 / 握 / 攥 / 摩挲 / 上手 等一律不出现）；「送礼」在叙事里是**心意的具象**，不是投喂数值 |
| 2 | **系统绝不主动伤害玩家** | 亲密度**不随时间衰减**；唯一的「跌」只能由玩家自己的选择或客观疏忽造成，且**必定可挽回** |
| 3 | **开后宫 = 多线并列、互不锁死**（硬需求）**；但人心上不并轨**（v165e 修订） | 亲密度与心意都是 **per-string 独立存档**，⛔ 无总量上限、⛔ 无「选 A 锁 B」。**✅ 但开了就有人不痛快**——嫉妒/修罗场是**关系内的张力**，只压结局档位（GRAND ↔ HE ↔ NE），⛔ **绝不致 BE**（详见 `v165-修罗场与嫉妒系统设计.md`） |

> ⚠️ **术语纪律**：本系统中「送礼」的面向词统一为「**递一件**」；「礼物」入叙事后统一称「**手边的一件东西**」或具体物名（如「一只旧扣子」「一盏热茶」）。⛔ 按钮与正文不出现「好感度」「+N」这类数值腔作为主体句，数值只作辅助小字。

## 二、亲密度模型

### 2.1 档位标尺：**沿用文档八档，阈值一数不改**（代码 6 档升级为 8 档）

依据：`v165-故事大纲.md` §5.2 滋养贡献表、§七 称呼表、§十 恋爱门槛，**全部按八档写死**，是最高依据；代码 6 档是落后实现。

| 档 | 档名 | 阈值 | 沁灵称玩家 | 滋养贡献（岁除用） | 情感状态 |
|---|---|---|---|---|---|
| 1 | 照面 | 0 | 主人 | 0 | 认得你 |
| 2 | 眼熟 | 12 | 主人 | 8 | 记得你的习惯 |
| 3 | 相熟 | 30 | 主人 | 18 | 不用说话也知道你要做什么 |
| 4 | 同室 | 55 | **你** | 30 | 给你留灯、留门、留位置 |
| 5 | 通意 | 90 | **你** | 46 | 知道你不说的那半句 |
| 6 | 同心 | 140 | **你** | 64 | 你不在时{ta}有事做 |
| 7 | 相知 | 200 | **`{nick}`**（恋爱线后 → **`{lovecall}`**） | 86 | {ta}能替你拿主意 |
| 8 | 沁透 | 280 | **`{nick}`**（恋爱线后 → **`{lovecall}`**） | 110 | 不必解释 |

- `BOND_CALL_AT`：**60 → 90**（对齐新「通意」；否则 55-90 区间会提前改口）。
- **改口即进度标记**：档 1-3「主人」→ 档 4-6「你」→ 档 7-8 昵称。⛔ **不许跳档、不许提前**，改口必须由剧情自然带出（`v165` §7.1）。
- **旧档兼容**：`rec.bond` 是绝对值，改表只改阈值不改结构 → 老用户**不掉档**，只提前到达同档。**零迁移**。

### 2.2 涨法（总表）——主动为主、被动兜底

| 来源 | 数值 | 频次上限 | 性质 | 备注 |
|---|---|---|---|---|
| **陪伴**（自然日，打开即结） | **+1/天** | 回补封顶 90 天 | 被动 | 沿用 `settleBond`，+2 → +1 |
| **共修**（既有 plays 次数） | **+1/次** | **+2/日** | 被动 | 单次结算封顶仍 +20 |
| **递一件**（送礼） | **+4/件**（偏好命中 **+6**） | 全局 ≤2 件/日；**同一只 ≤2 件**（**第 2 件 ×0.5**，即 +4→+2 / +6→+3） | **主动** | 见 §三 |
| **照料三式**（擦净 / 静坐 / 理线） | **+2/次** | 各 1 次/日（合计 ≤+6） | **主动** | 三类串通用 |
| **夜话事件** | **+3** | 每事件一次 | 主动 | 复用 `NIGHT_EVENTS` |
| **主线章末 / 岁除节点** | 离散 **+5 ~ +15** | 按剧情 | 主动 | `addBond` |
| **纪念日 / 生日** | **+10** | 年一次 | 被动 | 沿用 :3002 |
| **回信** | **+3** | 按信 | 主动 | 沿用 :2921 |

**节奏兜底结论**（复算见 v164l §2.2）：零操作玩家 day 30 也能拿**照面/眼熟/相熟**三档；只做照料的玩家 day 120 可拿满；被动封顶不设「必须天天上线」。

### 2.3 ⛔ 与 `stageOf` 解耦（承重墙）

- `rec.bond` **绝不作为 `stageOf()` 的任何输入**。`stageOf()` 只读「天数 / 次数（既有 `plays`）」，**亲密度一个字都不写进去**。
- `rec.flags.bondLv` 只是**结局判定用的缓存快照**（岁除前由 `bondLevel(rec)` 写一次），**只读、不回写 `stage`**。
- 反向亦然：`stage` 提升**不加** `rec.bond`（不靠挂机式联动）。两者只在**内容解锁**上取交集（`max(档位达标日, 阶段达标日)`）。

### 2.4 上限 / 频次 / 是否可跌

| 问题 | 裁定 | 理由 |
|---|---|---|
| 有没有**总量上限**？ | **无**（`rec.bond` 硬顶 99999，等同于无） | 开后宫已定：per-string 独立、总量不设限 |
| 有没有**每日上限**？ | **有**——但只压「刷」，不压「玩」：共修 +2/日、送礼 ≤2 件/日、照料 ≤+6/日 | 防单日刷爆，同时**不制造「必须天天上线」的惩罚**（陪伴走 90 天回补，回归玩家不落后） |
| 会不会**随时间下跌**？ | **不会**。陪伴是「打开即结」的正向回补，**没有衰减项** | 公理 2：系统绝不主动伤害玩家 |
| **唯一可能的「跌」**（**✅ 已定**） | **系统永不自动倒扣**。仅保留剧情写死的极少数点：玩家**主动做出伤害性选择**（叛出等剧情节点）→ 由**剧本写死**扣分，⛔ 系统不自动扣；另 ② `harmed=true` 期间亲密度**涨得慢（×0.5）**而非倒扣（已启用） | 依据用户最高铁律「系统绝不主动杀死 / 删除任何文玩」——亲密度同理，系统不许自动扣 |
| **冻结**（防挂机式后宫） | 30 天不互动 → **心意轨续期暂停（不扣分）**；**羁绊完全不受影响** | v164l §2.4/§5.2：冻结≠掉分，绝不清零（同理心底线） |

## 三、送礼系统

### 3.1 礼物从哪来（8 条自洽来源，全部 O(n) 单遍）

⛔ **不凭空发放**；每件礼物都有世界观内的来处。**全部按「日期 × 单只」计算，无一处串两两枚举**。

| # | 来源 | 产出 | 节奏 | 依托现有代码 |
|---|---|---|---|---|
| 1 | **节令** | 1 件应节物 | 约 1 件/2.5 周 | `FEST_*` / `festOf` ✅ |
| 2 | **修行破阶** | 1 件开光物 | 终身 4 件 | `stageOf` **检测到 stage 提升**时发（对比 `rec.bondLvSeen`）✅ |
| 3 | **沁灵巷小事** | 命中特定主题给 1 件 | 约 1 件/2 天 | `TOWN_EVENTS` ✅ |
| 4 | **同屋契合** | 每跨一个 `STORY_STEPS` 给 1 件 | 终身 5 件 | `STORY_STEPS=[7,20,40,70,110]` ✅ |
| 5 | **夜话事件** | 24 条里挑 8 条带奖励 | 约 1 件/1.5 周 | `NIGHT_EVENTS` ✅ |
| 6 | **主线章末** | 12 章里 8 章各 1 件 | 前 80 天 | 主线脚本 ✅ |
| 7 | **成就** | 首次破阶 / 同一只收满 3 件 / 集齐五类偏好 | 稀疏 | 需新建（`recordEvent`） |
| 8 | **每日一签** | 偶发「今日宜赠」 | 约 1 件/周 | `SIGNS` ✅ |

**库存形态**：礼物是**玩家级**（不是每只一份）；**送出后按只记账**（`rec.giftLog`）。

### 3.2 偏好机制：5 组人格 × 6 类礼物

> 依据 `v164l §3.2`，与 `v165 §2.7` 人物设定卡的 15 人格型对齐。**偏好只挂在人格上**；阶段与族类只改措辞、不改命中。

| 人格组 | 涵盖 | 偏好类 | 典型物 |
|---|---|---|---|
| **软** | gentle / sweet / sentimental / scholar | 织物类 | 旧帕、暖石、护身香囊 |
| **动** | lively / cheeky / heroic / wanderer | 声响类 | 铜铃、彩绳、小拨鼓 |
| **素** | cool / aloof / dignified / calm | 器物类 | 白瓷茶则、素砚、旧香 |
| **奇** | mystery / pampered | 奇异类 | 琉璃小件、贝壳、会响的怪石 |
| **野** | wild | 坚韧类 | 皮绳、磨刀石、粗布护腕 |
| （通用） | 全 15 型 | 人情类 | 一碟点心、一盏热茶（+4，不偏不倚） |

**命中规则**：命中偏好 **+6**，未命中 **+4**。**一只只有一类偏好，但 6 类都能递**——「送对」是划算，**不是「送错就白费」**。

### 3.3 送礼交互流程（节点图）

```
rec（某只）· 详情页「心迹」区
  ├─ 入口：按「递一件给它」（不设独立页，不打断陪伴动线）
  │     └─ [资格校验] bond >= 相熟(30)?
  │           ├─ 否 → 弹一句：「{ta}还没到接你东西的分上。」（不扣物、不消耗）
  │           └─ 是 → 打开「选礼抽屉」
  ├─ 选礼抽屉（单遍扫描库存，列出今日可递）
  │     ├─ 命中偏好 → 标「{ta}会喜欢这一类」（+6）
  │     ├─ 已送过   → 标「{ta}已经收着呢」（置灰，不可选，不消耗）
  │     └─ 今日已递满 → 标「今天递得够多了。明天再说。」
  ├─ 点某件 → 二次确认（confirmModal）
  │     └─ [递减校验] 同一天第 2 件 → ×0.5（+4→+2）
  └─ 送出演出 → 反馈闭环
        ├─ 台词（按 §2.7 语言习惯分型，见 §3.4）
        ├─ 数值：rec.bond += 4 或 6；rec.heart += 0（送礼不走心意）
        ├─ 记账：rec.giftLog[giftKey]=today；rec.giftDay=today；库存 -1；rec.giftTotal++
        └─ 表现：心迹条推进动画 + 小字「羁绊 +6」+ 今日可递 0/2
```

### 3.4 反馈演出：按人格型的反应台词（供文案参考，非最终稿）

> ⛔ 口径：**写{ta}做了什么小事，不写{ta}有多喜欢**（v164l §6 改写法则）。反应**分型**，同型不同人说不同的话。

| 人格型 | 命中偏好（+6）示例反应 | 未命中（+4）示例反应 |
|---|---|---|
| `dignified` 最老的那只 | 「东西我收下了。规矩我记着。」 | 「放那儿吧。回头用得上。」 |
| `scholar` 记账的 | 「嗯。这一件，我记在账上了。」 | 「……记一笔。」 |
| `cool` 不爱说话的 | 「……还行。」（说完就收进袖中） | 「嗯。」 |
| `gentle` 安静的 | 「你从哪儿找来的。」（说完去把灯拨亮一点） | 「搁这儿就好。」 |
| `lively` 最吵的 | 「我先看见的！我先看见的！」（声音一下子高起来） | 「哦——那我也要。」 |
| `mystery` 知道点什么的 | 「谁家的都行。这一件，是你会挑的。」 | 「有心了。」 |
| `sweet` 最小的 | 「这是给我的？真的？那我先拿着了！」 | 「……那我也收着。」 |

## 四、与其它系统的接口（数据契约 · 重点）

### 4.1 → `stage`（修行晋阶）：**无关，只校验不写入**
- 送礼 / 照料 / 亲密度**均不推进** `stageOf`。`stageOf` 只读「天数 / 次数」。
- 送礼 UI 若需展示修行进度，**只读** `stageOf(item,rec)`，⛔ 不写回。

### 4.2 → 岁除法力（滋养贡献）
```
滋养贡献 = f(档位)      // 查 §2.1 表：0/8/18/30/46/64/86/110
```
- **只读** `bondLevel(rec).lv`，⛔ 不改任何数值。与 `v165 §5.2` 表②**逐数对齐**。

### 4.3 → 恋爱线（开后宫 · 多线并列）
```
恋爱条件（逐串独立判定）：
  stageOf(item, rec, now) >= 4
  AND bondLevel(rec.bond).lv >= 7      // 相知
  AND rec.loveLine == true             // 玩家在「心迹」页显式点过「我想和{ta}更近一步」
```
- ⛔ **不锁章、不锁天**（v165 §10.1 第 4 条、§12-2）。⛔ 触发检查里**不得含天数条件**。
- **多线并列（机制层）**：每只**各自**有 `loveLine`，⛔ 无「已选 A 则 B 不可选」。⚠️ **但「机制不排斥」≠「相安无事」**——人心层的嫉妒另计（见 `v165-修罗场与嫉妒系统设计.md`，v165e）。
- **婉拒不锁死**：拒绝某只只把该只的 `loveLine` 置回 false，**门一直开着**；⛔ 不惩罚、不疏远。
- **门控落三处**（v164l §8.1，架构师照做）：入口 `intimateAct()` / 开关 `heartLineOn()` / 读取 `intimateSceneOf()`，**三处都要判 `stage>=4`**，不信任调用方。

### 4.4 → 称呼（档位决定）
```
callFor(rec):
  if rec.loveLine && rec.lovecall != ""  → rec.lovecall      // 恋爱专属，覆盖
  else if lv >= 7                        → rec.nickCall || "你" // {nick} 未填回落「你」
  else if lv >= 4                        → "你"
  else                                   → "主人"
```
- ⛔ 全篇 0 处敬称（您 / 大人 / 尊上 / 恩主 / 老爷）。
- `{lovecall}` **逐串、可重复填**（不同沁灵可同称呼）、**一经设定永久不可改、回环点不重填**（★ 主理人 2026-10-03 裁定：回环点只重置那一年，不重置任何情感资产——见 §4.5 / §九-4）。

### 4.5 → 回环点（回一口气）
| 资产 | 过回环点 | 依据 |
|---|---|---|
| `rec.bond` / 档位 | ✅ **永不重置** | v165 §6.3 |
| `rec.heart` / `rec.heartLog` | ✅ **永不重置** | 同上 |
| `rec.loveLine` / `rec.lovecall` | ✅ **永不重置、永不重填** | 用户 2026-10-03 裁定：「回气重来的是那一年，不是那些情分」；★ 主理人补充：`{lovecall}` **即使回环点也不重填** |
| `rec.giftLog` / `rec.giftTotal` | ✅ **永不重置** | 「同一礼物终身 1 次」需跨周目成立 |
| `rec.nickCall` | ✅ 保留 | v165 §6.3 |

### 4.6 → `harmed`（受伤）：**只慢不扣**（★ 主理人已裁定**启用**）
- 生效规则：`harmed === true` 期间，亲密度获取 **×0.5**（不清零、不倒扣）；`harmed` 清除即恢复。可经 `opts.harmSlow` 关闭（代码默认已开）。
- ⛔ `harmed` **不参与 `scattered` 判定**（v165 §5.9）。本设计**只读取**，不写入。
- ✅ **已裁定启用**（见 §九-1，裁定记录见文首）。

## 六、防刷与边界

| 边界 | 规则 | 防的是什么 |
|---|---|---|
| 单日刷爆 | 共修 +2/日、**全局**送礼 ≤2 件/日（**同一只 ≤2 件、第 2 件 ×0.5**）、照料 ≤+6/日 | 「一天把所有内容刷完」 |
| 单物刷满 | 同一礼物对同一只**终身仅 1 次**（`rec.giftLog` 命中即拦，**不消耗库存、不加分**） | 一件东西刷成万能钥匙 |
| 一盒分多只 | 同一礼物对**不同只各 1 次** ✅ | **这是「博爱」的载体**——一盒点心分给几只 |
| 重复发放 | 各来源按 `ww_story.giftSeeded[sourceKey]` 去重 | 同一次节令重复领 |
| 回归玩家 | 陪伴走 90 天回补、无衰减项 | 「几天不上线就落后」的惩罚式设计 |
| 挂机式后宫 | 30 天不互动 → 心意**冻结续期**（不扣分） | 防「开了线就不管」，但绝不清零 |
| 离线 | `ww_gifts` 本地优先；联网后与 `gift_store` 合并 | 断网也能玩 |
| 跨设备冲突 | `gift_store` 整库 **last-write-wins**（同 `spirit_store`） | ⚠️ 已知风险：A/B 两台同时加库存可能互相覆盖 → **建议改为「按 giftKey 取 max」合并**（见 §七-15） |
| `marks` 误删 | 本系统字段**零进 marks** | 规避既有字典序 bug |
| 旧档兼容 | `rec.bond` 为绝对值，改阈值不改结构 | 老用户不掉档、零迁移 |
