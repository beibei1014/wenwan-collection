## 3. 硬约束

1. **100+ 只串**：绝不枚举两两组合（100只=4950对）。一律 O(n) 扫描。列表/头像组折叠成"前 N 个 +M"。
2. **0 模型调用**：剧情是写死剧本 + 分支状态机。禁 AI 实时生成。
3. **数据体积**：跨手机同步走整库一行 JSON。新字段必须能进 `pruneForQuota`。
4. **无构建 vanilla JS**：改完必须能直接部署 GitHub Pages。
5. **行尾**：`app.js` / `skin.css` 是 **CRLF**。用 Python 改文件时**禁止** `newline=''` 读入后再 `newline='\r\n'` 写出（会产生 `\r\r\n` 双 CR，导致 git diff 显示整份文件全改）。正确做法：读入后归一成 `\n`，写出再转 `\r\n`；或写完后 `replace(b'\r\r\n', b'\r\n')`。
6. **index.html 的 script 带 `?v=`**：改完 JS 必须一起 bump（这次连带 skin.css）。

## 5. 任务 B：CG 存储改 IndexedDB 🔴

### 问题（已核）

`pruneForQuota()`（`spirits.js:83-84`）的**第一个动作**就是 `if (r.cgUrl) r.cgUrl = "";`，原注释"配额超限时尽量保住最新一张立绘：丢 CG"。

这在 CG 只是"随手重画的插画"时成立，但**主线 CG 是收集品**，逻辑反了：
- 8 张 data URI ≈ 1.6MB 塞主 store，挤爆配额
- 玩家看到「昨天还在的 CG 今天没了」
- 格子倒退回未解锁状态 —— **防剧透机制反而变成剧透**

### 方案

- **CG 像素 → IndexedDB（库 `ww_cg`）**，主 store 只留元数据
- 🔴 **「已收集」判定必须以元数据为准，不能以"图还在不在"为准**
- **换设备**：`ww_spirits` 跨手机同步，但 IndexedDB 不同步。新增第四种格子状态：

| 状态 | 含义 |
|---|---|
| `locked` | 没解锁 |
| `pending` | 正在画 |
| `failed` | **从没画成功过**（可重画） |
| `missing` | **画成功过，但像素不在这台设备上**（换手机） |

`missing` 视觉上**不能**像 `locked`（玩家以为进度丢了），也**不能**像已解锁（点开是空的）。要显示"这张图在原来那台设备上" + 「重新生成」入口（走 confirmModal，钱是用户的）。

## 7. 任务 D：CG 相册实现

规范见 `docs/v163-CG相册与美术规范.md`（UI 美术产出，待命名修正版）。

关键决策（已拍板）：
- **路由用顶层 `#/album`**，不能挂 `#/night/album` —— `router()`（app.js:7852）对 `#/night/` 前缀做 `split("/")`，`album` 会被当会话 id 丢给 `renderThreadPage()`
- **大图查看器另做 `#cgViewer`，不动 `openSpiritViewer`**（现有 3 个调用点：精灵 CG / 节令 CG / 房间剧情 CG，一行不改）。抽 `bindViewerDismiss()` 给两个查看器共用
- `#cgViewer` z-index **210**（`#viewer` 200 / toast 300）
- **必须 pushState**，否则安卓返回键关的是整页
- 大图查看器内**只保留当前 ±1 共 3 个 slide**（虚拟化）
- 长按 **480ms** 才弹保存确认（防误触）。三级回落：`navigator.share({files})` → `<a download>` → toast「请长按图片保存」
- class 前缀：容器 `album-`、图片 `cg-viewer-*`、格子数据属性 `data-cgid`（`data-cg` 已被 `.ft-cgimg` 占用）
