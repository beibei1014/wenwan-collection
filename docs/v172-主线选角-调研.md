## 2. 我方 vs 非我方判定

**结论：下拉框里只放第 1.1 节的 7 个槽位。** 依据三条：

1. `CHAP_CAST_CFG.MAIN` 只列了这 7 型（`js/spirits.js:6998`）—— 现有 casting 的边界就是这 7 个。
2. 剧本内证：收旧物的老头说「你们这七个」。
3. 非我方 10 个的台词里全部自称「我们 / 我从星月坛来 / 门客两位」，与「你们家」对举（见 1.2 表）。

**待定项（建议默认不进下拉，但留开关）**：邻居·爱往外跑的 / 邻居·嘴快的。
它们也是沁灵（同物种、叫玩家「当家的」），只是「巷尾那家」的。若主理想让玩家给邻居也配脸，这 2 个是最合理的扩展位；但**它们不在 `CHAP_CAST_CFG.MAIN` 里**，扩展需同时改 `MAIN` 数组 + `CHAP_CAST_NAME`。
⛔ 掠客 / 门客 / 收旧物的老头 / 坛主 = 人类，⛔ 星月坛三位 = 外坛的人形沁灵，这 6 个**永远不该**出现在下拉框。

## 4. 「当下已经是沁灵的角色」怎么判定

### 4.1 候选列表源（app 层，UI 直接用这个）

```

⇒ **判定表达式：`!i.gifted && i.playStatus === "done" && rec.spirit !== false`**（+ focus 模式下 category 属文玩类）。
⛔ **不要用 `stage >= 1`** —— `rec.stage` 老数据默认就是 1（`js/spirits.js:410`），筛不掉任何东西。
⛔ **不要用 `birthAt`** —— 该字段不存在；相关的是 `rec.bornAt`（`js/spirits.js:435-436` 生成时补），且老数据也可能没有。

### 4.2 「能不能演」的附加条件

`castBuild()` 只收 `personaIdOf(rec) !== ""` 的（`js/spirits.js:7038-7042`）：
```
js/spirits.js:3275-3280  function personaIdOf(rec) { return rec.look?.pers || rec.persona?.id || ""; }
```
⇒ 无 persona 的串（还没抽人设）**现在进不了自动抽签池**。但**手动选角是直选 id，不依赖 persona**，所以下拉框可以放宽到 `spiritItems()` 全部（无 persona 的演起来只是没 persona 名，立绘照有）。建议：放宽，但在选项上标「（未定人设）」。

### 4.3 显示名（本名 / 昵称 / 用户改名）

```
js/app.js:4031-4033  function nameOf(it, store) {

- `rec.name` = **用户改过的名**（最高优先）
